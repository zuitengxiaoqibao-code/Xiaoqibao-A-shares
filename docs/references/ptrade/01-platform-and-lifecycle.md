# 平台、生命周期与运行语义

## 平台形态

- PTrade 客户端运行在 Windows，本地客户端通过 HTTP/HTTPS 连接云端量化模块。
- 策略部署在券商服务器的隔离环境中。官方 FAQ 描述了加密存储和容器隔离，但实际安全与资源上限仍以券商部署为准。
- 官方 FAQ 当前标注 Python `3.11.4`；文档同时保留 Python 3.5 依赖清单，用于历史策略兼容。
- 研究环境用于数据清洗、建模、绘图和调试；回测环境用于历史撮合；交易环境连接模拟或实盘账户。
- 研究、回测、交易可读取 2005 年以来的历史行情和财务数据；实时快照、逐笔与实际下单依赖交易环境和权限。
- 云端策略不能直接读取本地路径。研究根路径可由 `get_research_path()` 获取，官方示例为 `/home/fly/notebook/`。
- 当前官方 FAQ：不支持 macOS、离线回测、自主升级三方库、跨策略调用、自有包导入、本地数据库直连和 `requests`。

## 运行周期和时间

| 周期 | 回测 | 交易 | 运行语义 |
| --- | --- | --- | --- |
| 日线 | 支持 | 支持 | 回测通常 15:00；交易默认 14:50，券商可配置 |
| 分钟 | 支持 | 支持 | 每根分钟 K 线结束触发 |
| Tick | 不支持 | 支持 | `tick_data` 固定约 3 秒；`run_interval` 最小 3 秒 |

官方时间段：

- 盘前：09:30 前；可运行 `before_trading_start`，交易可运行盘前 `run_daily`。
- 盘中：回测约 09:31-15:00，交易约 09:30-15:00；可运行 `handle_data`，交易还可运行 `tick_data`、`run_interval`。
- 盘后：`after_trading_end` 通常在 15:30；交易可在 15:00 后安排 `run_daily`。

这些时间不是交易所事实的替代品。券商可调整日线策略触发时间，策略必须记录实际触发时间和交易日。

## 生命周期事件

| 事件 | 签名 | 环境 | 核心职责 |
| --- | --- | --- | --- |
| `initialize` | `initialize(context)` | 回测/交易 | 初始化全局状态、股票池、基准、费用和任务；必选 |
| `before_trading_start` | `before_trading_start(context, data)` | 回测/交易 | 每日盘前准备；可选 |
| `handle_data` | `handle_data(context, data)` | 回测/交易 | 日线/分钟主逻辑；必选 |
| `after_trading_end` | `after_trading_end(context, data)` | 回测/交易 | 盘后落地、复盘与核对；可选 |
| `tick_data` | `tick_data(context, data)` | 交易 | 约 3 秒级行情处理；可选 |
| `on_order_response` | `on_order_response(context, order_list)` | 交易 | 委托主推，比轮询订单更快；部分柜台不支持 |
| `on_trade_response` | `on_trade_response(context, trade_list)` | 交易 | 成交主推；可选 |

官方锚点：[生命周期章节](https://ptrade.i618.com.cn:7766/hub/help/api#策略引擎简介)。

## 线程与顺序

交易中的 `before_trading_start`、`handle_data`、`tick_data` 和 `run_interval` 是独立线程，理论上没有固定先后顺序。开盘期间启动交易时，`before_trading_start` 和 `handle_data` 甚至可能同时运行。

因此策略需要显式状态机：

1. 盘前数据准备完成后才打开盘中计算开关。
2. 每个交易日使用唯一日期状态，避免昨日状态污染。
3. 订单意图带唯一 ID，回调只推进状态，不无条件再次下单。
4. 同一共享数据结构要考虑并发读写，尽量采用不可变快照或单写入线程。
5. `tick_data` 单次处理超过约 3 秒会丢弃中间事件，AI 推理和网络 IO 不应放入同步回调。

## 持久化与重启

框架会在 `before_trading_start`（隔日开始）、`handle_data`、`after_trading_end` 后更新持久化信息，保存可序列化的股票池、账户信息、订单信息和 `g` 变量。

关键语义：

- 环境重启恢复时先运行 `initialize`，再恢复持久化内容；同名 `g` 变量会被持久化值覆盖。
- `g` 中以 `__` 开头的变量不保存；文件句柄、实例化对象等不可序列化对象也不会保存。
- 官方 FAQ 对“重启”的描述是重新创建交易 ID，未另行保存的内存变量会清除。
- 不要在 `initialize` 或启动阶段放置无幂等保护的下单逻辑。
- 框架持久化不是审计账本。项目桥接仍需独立保存任务 ID、交易日、数据校验和、订单意图和处理状态。

## 支持业务与价格精度

回测包含股票、可转债、两融担保品、期货、LOF、ETF；交易还包含 ETF 申赎/套利、国债逆回购及完整两融。当前项目仍只面向 A 股和独立可转债，不因此扩展到期货或期权。

| 品种 | 最小价差/限价精度 |
| --- | --- |
| 股票 | `0.01`，两位小数 |
| 可转债 | `0.001`，三位小数 |
| ETF/LOF | `0.001`，三位小数 |
| 国债逆回购 | `0.005` |
| 股指期货 | `0.2`，通常一位小数 |
| 国债期货 | `0.005` |

价格精度错误会直接造成委托失败。证券代码常用 `.SS/.SZ`，对象返回值也可能出现 `.XSHG/.XSHE`，桥接层必须统一规范化并保留原始代码。
