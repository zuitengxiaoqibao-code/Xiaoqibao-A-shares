# 设置、调度与回测约束

## 设置函数

| 函数 | 作用 | 关键限制 |
| --- | --- | --- |
| `set_universe` | 设置/更新股票池 | 股票策略中主要作为 `get_history` 默认证券列表，并非所有策略都必须设置 |
| `set_benchmark` | 设置收益评价基准 | 可用指数、个股或 ETF，影响前端策略评价 |
| `set_commission` | 设置回测佣金和最低佣金 | 仅回测；应按账户真实费率配置 |
| `set_fixed_slippage` | 固定金额滑点 | 仅回测；与比例滑点不要重复表达同一成本 |
| `set_slippage` | 比例滑点 | 仅回测；用于逼近真实成交偏差 |
| `set_volume_ratio` | 限制单笔成交占分钟量比例 | 仅回测；用于流动性冲击模拟 |
| `set_limit_mode` | 选择是否受成交量限制 | 仅回测；低频调仓可选择不限制，高频策略应保留限制 |
| `set_yesterday_position` | 设置股票回测底仓 | 仅回测；可与 CSV 转换函数配合 |
| `set_parameters` | 设置交易策略参数 | 仅交易；包含重启等运行配置，需按目标版本核验 |
| `set_email_info` | 配置交易报错邮件 | 仅交易；依赖券商外网能力 |

完整签名见 `api-catalog.md`，官方入口：[设置函数](https://ptrade.i618.com.cn:7766/hub/help/api#设置函数)。

## 调度函数

### `run_daily`

签名：`run_daily(context, func, time='9:31')`。

- 回测与交易可用。
- 适合盘前、盘中指定时点、盘后任务。
- 任务必须按交易日幂等，补跑或重启不能重复生成订单或重复覆盖已验证数据。
- 日线回测和交易默认触发时刻不同，不能把代码中的时间假设当作统一事实。

### `run_interval`

签名：`run_interval(context, func, seconds=10, interval_timer_ranges='')`。

- 仅交易可用。
- 股票等业务最小间隔 3 秒。
- `interval_timer_ranges` 用于限定运行时间范围，是最新版本线索 `.032` 的新增参数。
- `run_daily` 与 `run_interval` 创建的任务线程总数上限为 5；阻塞中的任务不会累积补执行。
- 高频任务只做轻量采集、校验与入队，耗时分析交给异步工作线程。

## 回测逼真度

回测至少要同时控制：

1. 佣金、最低佣金、印花税和实际市场规则。
2. 固定或比例滑点。
3. 成交量比例与成交数量限制模式。
4. 停牌、涨跌停、最小价差和数量单位。
5. 不复权撮合价与复权分析序列的口径差异。
6. 财务数据的首次披露时点，防止未来函数。

官方 FAQ 指出回测可同时运行 5 个；部分在线接口如 `get_fundamentals`、`get_Ashares` 会受网络影响，应该盘前/批量缓存而不是在每根 K 线重复调用。

## 调度设计建议

| 阶段 | PTrade 事件 | 本项目职责 |
| --- | --- | --- |
| 盘前 | `before_trading_start`、盘前 `run_daily` | 更新证券池、状态、上一交易日数据、新闻证据和观察名单 |
| 盘中 | `handle_data`、`tick_data`、`run_interval` | 采集快照、检查触发条件、风险提醒，不同步执行大模型推理 |
| 盘后 | `after_trading_end`、盘后 `run_daily` | 落地事实、核对数据覆盖、复盘信号、生成次日候选 |

本项目默认只生成辅助决策和人工确认建议。未来即使接入交易接口，也要让分析、风控与执行进程隔离。
