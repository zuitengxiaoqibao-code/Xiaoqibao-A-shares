## 部署与平台（1-6）

1. **关于量化环境**：客户端本地运行，量化模块云端部署，客户端通过 HTTP/HTTPS 连接云服务器。
2. **关于策略安全**：策略在券商服务器加密存储，官方描述使用容器隔离不同账户运行空间。
3. **Mac 是否支持**：目前不支持，只能在 Windows 环境使用。
4. **关于付费**：云纪仿真环境官方说明免费；券商部署的条件以券商为准。
5. **关于程序语言**：只支持 Python。
6. **关于 Python 版本**：当前 FAQ 标注 Python `3.11.4`。

## 数据（7-11）

7. **数据种类**：研究/回测/交易可调用 2005 年以来的历史财务和行情数据，包含分钟、日、周；交易支持 Tick 快照；覆盖股票、转债、指数等。
8. **关于数据读写**：研究环境可存文件，根目录可由 `get_research_path` 获取，官方示例为 `/home/fly/notebook/`；回测和交易可通过该路径读写。
9. **关于本地数据**：云端策略不能直接访问本地路径。
10. **关于行情除复权**：支持不复权、前复权、后复权、动态前复权；回测撮合价格不复权，需要自行处理分析序列与撮合价口径。
11. **关于 Level-2**：云纪仿真环境不提供；券商环境由券商决定。

## 研究与文件（12-15）

12. **研究环境资源**：FAQ 称单个客户研究环境资源目前没有上限；实际仍应以券商配额为准。
13. **文件传输限制**：手工上传/下载单文件不超过 50 MB。
14. **定时上传**：可从本地路径定时上传，但次数由券商限制，不适合高频本地数据交换。
15. **上传文件夹**：不支持整文件夹上传，需要逐个文件。

## 回测（16-25）

16. **回测与研究的区别**：研究适合清洗、建模、绘图和调试，不能调用订单/账户接口；回测适合完整交易策略、参数调优和历史收益评价。
17. **回测个数**：支持同时 5 个回测。
18. **回测速度**：`get_fundamentals/get_Ashares` 等在线接口受网络影响，应降低调用频次；分钟策略的日频数据可在盘前一次准备。
19. **回测周期**：只支持分钟和日线回测。
20. **调试功能**：回测模块支持调用堆栈、变量监视和本地变量查询。
21. **性能分析**：可统计语句触发次数和耗时，用于定位性能问题。
22. **离线回测**：不支持，回测期间客户端必须打开。
23. **策略上传/下载**：支持加密上传下载，用于跨账户隐藏代码地运行模拟交易；不等同于跨策略函数调用。
24. **撮合与真实成交限制**：`set_limit_mode` 可选择受分钟成交量限制或不受限制；后者更适合低频调仓，不适合高频逼真回测。
25. **获取回测代码**：在回测记录详情中查看对应代码。

## 模拟交易（26-35）

26. **模拟交易个数**：默认可同时运行 5 个，券商可配置。
27. **客户端离线**：交易在服务器运行，客户端关闭或掉线不影响已启动策略。
28. **不同交易的账户管理**：模拟/实盘交易共享同一账户资金和持仓，不支持子账户隔离。
29. **交易开启时间**：可随时开启；会立即执行 `initialize` 和可选盘前回调。盘中开启时，盘前回调和盘中回调可能并发。
30. **模块顺序**：`before_trading_start/handle_data/tick_data/run_interval` 是独立线程，无固定先后，应自建阶段开关。
31. **重启**：重启等同新建交易并创建新交易 ID，未持久化内存变量会清除。
32. **回测与交易代码兼容**：可用 `is_trade` 在一套代码中区分回测与交易路径。
33. **模拟交易稳定性**：主要风险来自历史 K 线不完整、实时快照失败、财务接口在线请求失败和服务器环境异常。应校验请求数量/返回长度/去重长度，检查快照非空和字段非零，财务请求加重连和缓存，并使用持久化保证重启连续性。
34. **账户数据更新频率**：资金、持仓、订单、撤单等理论上约 6 秒同步一次，应使用中间状态避免重复交易。
35. **`tick_data` 与 `run_interval`**：都可做 Tick 周期策略；前者固定约 3 秒，后者最小 3 秒且可配置，数据源均为快照，可选其一。

## 实盘（36-37）

36. **开通实盘**：向开展 PTrade 业务的所在券商申请。
37. **实盘与模拟差异**：数据获取机制一致，主要差异是成交撮合机制；仍需在目标柜台单独验证。

## 委托（38-42）

38. **快照失败导致委托失败**：限价系列函数未传 `limit_price` 时会用最新价；空快照可能形成废单，应检查废单并安全处理，不盲目重复下单。
39. **委托数量**：必须是整数，否则失败并返回 `None`。
40. **集合竞价下单**：支持，可参考官方集合竞价示例。
41. **委托状态监控**：`get_orders` 约 6 秒同步本策略订单；交易可用 `on_trade_response` 获取更快的成交主推。
42. **撤销手工委托**：`get_all_orders` 获取账户全部订单，再用 `cancel_order_ex` 撤单；必须严格过滤目标订单。

## 三方库（43-44）

43. **查询三方库**：研究环境中执行 `!pip list` 查看实际包和版本。
44. **三方库更新**：不支持用户自主更新。

## 其他（45-55）

45. **调用自有包**：策略不支持导入自有包，也不支持跨策略调用；单策略需要在一个文件实现。
46. **连接自己的数据库**：因合规限制不支持本地数据库直连；可上传 DB 文件并用 Python 自带 `sqlite` 读写研究环境文件。
47. **信号推送**：可使用邮件或企业微信接口，但依赖券商是否开放外网。
48. **OS 模块**：`os` 不能使用；创建目录用 `create_dir`。
49. **快速获取最新价**：回测用 `data[stock].price`（不复权）；交易用 `get_snapshot`。
50. **日线策略运行时间**：回测 15:00；交易默认 14:50，券商可配置。
51. **`get_history(include)`**：默认 `False`；`True` 包含当前周期。日线回测可用于提速，其他场景谨慎使用。
52. **基准设置**：支持指数、个股和 ETF，参见 `set_benchmark`。
53. **跨周期处理**：可组合 `run_interval` 与 `handle_data`。
54. **`requests`**：当前不能使用。
55. **批量委托性能**：官方测试口径为 300 笔约 2 秒，不应视为目标券商 SLA。

## 项目执行结论

- PTrade 不是本地服务的网络 SDK，不能依赖 `requests` 从策略主动回调本项目。
- 可行方式是研究目录文件导出、定时上传/下载或券商认可的专用桥。
- 所有在线接口都要做缓存、长度校验、空值保护、重试上限和来源健康记录。
- 同账户多策略共享资金持仓，未来执行前必须有跨策略资金与订单协调层。
