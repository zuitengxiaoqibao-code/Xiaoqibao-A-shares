## AI 状态基线

可观测性账本共有 152 条事件：

- `realtime_ai`：105 次 `unavailable`，10 次 `ready`。
- `source-health-snapshot`：37 次 `error`。

因此，页面将“AI 未配置或暂不可用”作为单一文案是不准确的。阶段 2 必须
把未配置、未验证、连接失败、超时、限流、模型不存在和规则回退分开，并保留
真实中文原因；规则分析在 AI 不可用时仍应继续展示。

## 当前根因假设（待阶段 1/2 验证）

1. API 中间件已有延迟记录，但没有统一 `trace_id`、缓存来源和响应覆盖度，导致
   页面无法解释“为什么慢、是否命中缓存、为什么没有数据”。
2. 前端请求账本把 `cacheHit` 默认记录为 `false`，无法区分未记录与真实未命中。
3. 慢接口与页面首屏耦合，失败或空响应存在覆盖旧快照的风险。
4. 公司研究、新闻提醒和运维状态的慢任务没有统一的后台任务边界。

## 阶段 0 验收结论

基线审计已完成。下一步先以失败测试固化快照裁决规则，再实现统一运行快照
契约；在契约通过前，不对量化和公司研究做大规模重构，避免继续放大数据串扰。
