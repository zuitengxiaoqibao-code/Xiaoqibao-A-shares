# 量化候选后台预热设计

**目标：** 让便携 EXE 首次打开量化分析时先立即展示真实市场状态和动态扫描状态，再由后台线程完成全市场日线候选扫描，避免 6 秒级扫描阻塞页面。

## 约束

- 候选必须来自本地已验证日线和现有候选因子计算，不生成随机或静态推荐。
- 后台扫描完成前，候选列表为空并明确标记 `pending`；扫描失败明确标记 `failed`。
- 只有后台扫描成功并经过现有 `CandidateBoard` 校验后，才进入候选池缓存。
- 缓存仍遵守现有 30 秒 TTL；触发证据仍遵守 5 秒 TTL。
- EXE 退出时必须取消后台线程，不能留下应用进程或端口占用。

## 架构

`QuantStrategyService` 在便携运行时使用单线程执行器管理一个 `(交易日, limit)` 扫描任务。请求线程只读取市场总览、检查缓存和任务状态；首次无缓存时提交任务并返回一个不含候选的 `partial` 仪表盘。后续 5 秒轮询发现任务完成后，消费结果、写入内存缓存并重新计算策略与触发证据。

响应新增三个可观测字段：

- `candidate_scan_state`: `ready`、`pending` 或 `failed`
- `candidate_scan_started_at`: 后台任务开始时间
- `candidate_scan_error`: 失败原因（仅内部可行动文本）

扫描阶段进一步细分为：

- `candidate_scan_phase`: `loading_history`、`computing_factors`、`ranking`、`ready` 或 `failed`
- `candidate_scan_processed` / `candidate_scan_total`: 仅在逐股因子计算实际推进时填充真实计数

前端只在 `computing_factors` 且 `total > 0` 时计算百分比；历史读取和排序阶段继续显示无确定百分比的动态等待。

前端状态栏将扫描状态显示为“后台预热中”“扫描失败”或原有的“刚刚采集/复用缓存”。

## 测试与验收

- 服务单测验证首次请求不等待候选扫描、后台完成后下一次请求返回真实候选。
- 既有量化缓存年龄、触发证据和历史日期拒绝测试必须保持通过。
- 前端量化、首页和短线策略工作台测试必须通过。
- EXE smoke 必须确认窗口先出现、专业字段仍诚实显示 `unavailable`、退出后没有残留进程。
- `pending` 状态必须使用无确定进度动画和已运行时间；只有扫描器提供真实处理数量/阶段后才允许显示确定百分比。
- 因子扫描阶段的百分比必须由 `processed / total` 得到并限制在 0–100；不得通过计时器、平均速度或固定步长伪造。

## 桌面启动状态补强

便携 EXE 启动页额外读取 API 写入的启动里程碑日志。状态解析器只接受白名单阶段，并将其映射为低于“API 已就绪”的阶段提示；读取失败、未知阶段或日志尚未产生时保持上一条状态。窗口等待 API 的同时由可停止的后台线程轮询，API 成功或失败后立即停止并回收线程，避免残留控制或进程。
