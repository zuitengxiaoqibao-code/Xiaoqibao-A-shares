# 全站视觉统一与突发新闻股票提醒设计

## 目标

将当前多套视觉语言统一为深色专业行情终端，重点消除“信息总览”浅色高密度终端与“今日研判”深色决策终端之间的割裂。统一不意味着所有页面使用相同布局：页面仍按任务保留信息密度和操作结构，但共享同一套色彩、字体、边界、间距、状态和反馈规则。

同时将类似“突发异动”的新闻作为有证据的事件信号，与对应 A 股、题材和行业建立可解释关联，在信息总览、今日研判、个股详情和事件 K 线中使用一致的特别提醒。

## 非目标

- 不更改市场数据、候选股、决策或回测的计算逻辑。
- 不更改现有路由，不使已有书签失效。
- 不用模拟新闻、模拟行情或随机分数填补缺失数据。
- 不因全站统一而删减信息总览、今日研判等页面的真实功能。
- 不将宏观新闻无条件映射到大量个股。

## 统一设计原则

1. **结论和异常先于装饰**：亮色只用于实时、异常、风险、选中和关键结论。
2. **高密度但不牺牲可读性**：桌面端用稳定网格承载信息，移动端重排为单列或双列，不靠缩小字体硬塞。
3. **一致的市场语义**：A 股保持红涨绿跌；金色为观察或警告；青色为数据、实时和交互；灰色为缺失、过期或未验证。
4. **证据优先**：新闻和 AI 解释必须展示来源、时间、关联依据和置信状态。
5. **光效克制**：只在实时指示、重大突发、选中边框和顶级风险上使用微弱发光，不用大面积渐变或高亮背景干扰数据。

## 全站视觉基线

### 色彩令牌

CSS 将以语义令牌为主，页面不再定义独立的浅色变量体系。推荐基线：

| 语义 | 值 | 用途 |
| --- | --- | --- |
| `--surface-canvas` | `#070b10` | 全站底色 |
| `--surface-base` | `#0b1118` | 页面工作区 |
| `--surface-raised` | `#101923` | 面板、表格头、选中行 |
| `--surface-emphasis` | `#15222d` | 强调指标和交互态 |
| `--border-subtle` | `#22313d` | 常规分隔线 |
| `--border-strong` | `#344a5a` | 选中、聚焦、重要分区 |
| `--text-primary` | `#dce7ee` | 标题和关键值 |
| `--text-secondary` | `#9fb0bd` | 说明和次要数据 |
| `--text-muted` | `#667987` | 来源、时间和缺失状态 |
| `--market-up` | `#f04f5f` | 上涨、正向、强势 |
| `--market-down` | `#2fcf91` | 下跌、负向、弱势 |
| `--status-warning` | `#e5b84b` | 警告、观察、待确认 |
| `--status-live` | `#39c8dd` | 实时、交互、数据新鲜度 |
| `--status-unavailable` | `#7d8993` | 不可用、未验证、过期 |

风险背景由上述状态色以 8%–12% 透明度生成，不再分散硬编码多组近似暗红、暗绿和暗黄。

### 字体和层级

- 数字、代码、时间、表格和主要正文使用 `JetBrains Mono` 及当前中文等宽回退字体。
- `Orbitron` 只用于英文窗口编号、仪表标识和短标题，不承载长中文正文。
- 主要正文不小于 12px，表格和次要标签不小于 10px，核心数值使用 16–24px。
- 字距保持 `0`，不使用负字距压缩字符。

### 几何与间距

- 主面板圆角为 0–3px，重复条目和弹窗最多 6px。
- 页面级区域使用无外层卡片的全宽分区，内容通过细边框和栅格划分。
- 基础间距序列为 4、8、12、16、24px，布局不再混用大量一次性值。
- 表格行高保持 30–36px，指标带高度保持稳定，加载和数据更新不引起布局跳动。

## 公共页面骨架

新增或收敛为可复用视觉原语，但不把所有业务组件抽象成一个巨型组件：

1. **PageHeader**：页面名称、任务说明、数据时间和顶层状态。
2. **StatusStrip**：数据源、覆盖率、新鲜度、交易阶段和风险模式。
3. **MetricBand**：稳定高度的关键指标组，支持涨、跌、警告、实时和缺失语义。
4. **TerminalPanel**：带有统一标题栏、副标题、右侧状态和内容区的工作窗口。
5. **DataTable**：统一表头、数字对齐、选中行、涨跌色、缺失值和窄屏滚动。
6. **StateNotice**：统一 loading、partial、stale、error 和 unavailable，明确区分“没有符合条件”与“数据不可用”。
7. **EvidenceBadge**：统一已验证、多源确认、待确认、题材联动和未验证标识。

业务页面只组合这些原语，数据获取和业务类型保持原有边界。

## 页面分类与布局

### 信息总览

信息总览从独立浅色终端转为深色高密度市场扫描终端，保留现有市场情绪、涨跌停生态、市场广度、成交、指数、异动、资讯、板块和功能菜单。

桌面端顺序：

1. 市场情绪与指数指标带。
2. 功能导航轨。
3. 主工作区：分时图、异动记录、突发事件流。
4. 板块、个股和当前功能的专项表格。
5. 数据来源、警告和仅供观察声明。

左侧或首屏中的突发新闻只展示高优先级事件，普通资讯仍在实时资讯流中，避免每条新闻都变成告警。

### 今日研判

今日研判保留“结论优先”的决策结构：

1. 页面标题与当前研判范围。
2. 市场风格、情绪、风险和数据可信度指标带。
3. 当日需要特别关注的突发事件和受影响股票。
4. 盘前研判、盘中检测、盘后复盘三阶段结论。
5. 不符合触发条件时明确显示“不提醒”或“继续观察”，不用空白代替结论。

### A 股观察与个股详情

- 自选股、短线候选和波段候选列表继续保持精简，详细情绪、证据和新闻在右侧个股工作区展开。
- 个股顶部增加稳定的“最新重大事件”提醒位，显示新闻时间、方向、置信度和关联理由。
- 事件 K 线现有的编号锚点、横向事件索引、选中详情条和红涨绿跌保持不变，只接入统一令牌。
- 一条新闻如果仅为题材联动，K 线标记和详情必须显示“题材关联”，不允许冒充公司直接事件。

### 研究工具和独立资产页

首次涨停、量化分析、新闻中心、回测、数据设置和可转债继续保留业务专属布局，但使用全站公共页头、指标带、面板、表格、按钮和状态组件。可转债保持与 A 股的资产边界，不将两者的候选池和指标含义混合。

## 突发新闻事件链路

### 数据源与优先级

1. 官方公告优先使用巨潮公告和本地通达信 F10 摘要。
2. 个股新闻和全球快讯使用已接入的真实公开数据源，保留发布者和原始链接。
3. 价格、K 线和事件时间定位优先使用本地通达信数据；通达信无法提供的独有新闻数据才使用受限流的外部源。
4. 任何源失败都显示真实状态，不生成示例新闻填位。

### 标准化和去重

每条新闻入库时保留：

- 原始标题、摘要、发布者、原始链接和内容哈希。
- 原始发布时间和本地采集时间，两者不混用。
- 归一化标题指纹和事件指纹。
- 被合并的来源列表、首次发布时间和最新更新时间。

内容哈希一致的转载直接去重；标题近似、主体和时间窗口一致的报道合并为一个事件聚类，界面显示来源数量而不是重复卡片。

### 股票关联等级

| 等级 | 条件 | 界面标识 | 能否触发个股特别提醒 |
| --- | --- | --- | --- |
| 直接关联 | 标题或正文明确出现合法 A 股代码、公司名称或官方公告主体 | 直接关联 | 可 |
| 上下文关联 | 新闻来自明确的个股上下文，且数据源本身按证券代码提供 | 个股来源 | 可，但必须显示来源上下文 |
| 题材联动 | 只命中行业、概念、供应链或地域关键词 | 题材联动 | 不直接告警；需额外证据达到阈值 |
| 宏观关联 | 仅与大盘、海外市场或宏观政策相关 | 市场影响 | 否，只进入市场或板块层 |

确定性规则先建立候选关联，AI 只负责解释影响方向、影响链和不确定性，不能凭空创建证券代码。

### 验证和提醒等级

`verification_state` 与 `urgency` 保持两个独立维度，避免把“突发”误当成“可信”：

- `verified`：官方来源，或可验证来源且直接关联充足。
- `multi_source_confirmed`：两个或以上相互独立的可验证来源报道同一事件。
- `pending`：单一来源、题材推导或关键事实仍需核实。
- `unverified`：来源无法验证或关联依据不足，不进入个股 K 线和决策证据。

`urgency` 为 `breaking`、`tracking` 或 `normal`，由事件类型、时效、价格异动和风险关键词的可解释规则产生，不使用随机数或固定假分数。

特别提醒必须同时满足：

1. 新闻时间未超过配置的时效窗口。
2. 事件不是 `unverified`。
3. 股票关联为直接关联或可追溯上下文关联；题材联动需另一个独立证据。
4. 未被用户稍后阅读、事件指纹或更高版本事件判定为重复。

### 影响解释

对通过最低验证门槛的事件输出：

- `impact_direction`：正向、负向、中性或影响待核验。
- `impact_horizon`：盘中、次日、短期或中期。
- `association_reason`：为什么与该股票、板块或题材相关。
- `evidence_summary`：已确认的事实。
- `uncertainty`：仍未验证的关键信息。
- `risk_note`：新手应避免的误解，例如“相关新闻不等于股价必然上涨”。

AI 解释不可用时，保留确定性关联和原始证据，影响方向显示为待核验，不阻断真实新闻展示。

## 突发新闻界面

突发事件卡保留截图中有价值的信息层级，但使用本项目统一深色视觉：

1. 首行：突发、跟踪、已验证、多源确认或待确认标签，以及可解释的关联置信状态。
2. 主体：最多三行新闻标题，不在窄卡片中堆放长段落。
3. 关联行：股票、行业、题材及“直接”或“题材联动”理由。
4. 影响行：方向、时效和一句话风险提示。
5. 底部：发布者、原始发布时间、来源数和原文入口。

突发事件使用金色或状态色左边框与微弱脉冲，不使用全卡高饱和背景。相同事件在不同页面使用同一颜色和标识含义。

## 数据流

```text
真实新闻/公告数据源
  -> 标准化原始文章
  -> 内容哈希去重与同事件聚类
  -> 确定性股票/行业/题材关联
  -> 来源验证与关联等级
  -> 可选 AI 影响解释
  -> 突发优先级与提醒门槛
  -> 本地事件库
  -> 信息总览 / 今日研判 / 个股详情 / 事件 K 线
```

前端只消费标准化后的事件合约，不在组件内通过标题字符串临时猜测关联股票。

## 错误、降级与新鲜度

- 新闻采集失败：保留上次成功快照，明确显示过期时长和失败数据源。
- 个股关联不足：新闻仍可进入市场或题材新闻流，但不进入个股特别提醒。
- AI 解释失败：显示原始事实和确定性关联，影响方向降级为待核验。
- 事件无对应交易日：保留事件记录，显示“非交易日，未落图”，不强行改写时间。
- 行情不可用：不展示伪 K 线；新闻列表可独立展示，同时说明暂时无法定位到 K 线。
- 市场休市：实时状态改为已收盘或休市，不把正常静止判定为数据中断。

## 响应式设计

- `>= 1440px`：保留高密度多列工作区，核心图表不被侧栏过度挤压。
- `900–1439px`：辅助资讯和证据区移到主图表下方，指标带允许换行。
- `< 900px`：主内容单列，表格水平滚动，功能轨和事件索引水平滚动。
- `< 600px`：指标带为两列或单列；突发事件卡显示两行标题和核心标识，详细证据点击后展开。

图表、指标带、操作按钮和表格都定义稳定的高度、网格或最小宽度，加载、Hover 和数值变化不得导致布局跳动或文字重叠。

## 无障碍和交互

- 所有颜色状态同时有文字或图标，不仅靠颜色区分。
- 数据表和事件列表保留清晰的键盘聚焦态。
- 按钮和可点击事件条目提供可读的 `aria-label`。
- 脉冲和扫描线遵循 `prefers-reduced-motion`，减少动效时不影响状态判读。
- 原始来源在新窗口打开，不在本地页面伪造转载内容。

## 测试与验收

### 前端

- 公共视觉原语的渲染、状态和可访问名称测试。
- 信息总览和今日研判的 loading、ready、partial、stale、error 和 unavailable 测试。
- 突发事件卡的直接关联、题材联动、多源确认和待确认测试。
- 事件 K 线继续验证编号锚点、事件索引、详情选中、红涨绿跌和移动端事件数量限制。
- 运行完整前端测试和生产构建。

### 后端

- 新闻内容哈希去重、近似事件聚类和来源合并测试。
- 直接代码、公司别名、个股上下文、题材关键词和宏观新闻的关联等级测试。
- 未验证新闻不进入个股决策证据或事件 K 线的门槛测试。
- AI 失效时保留真实新闻和确定性关联的降级测试。
- 非交易日、未有本地日线和截止时间防止未来数据泄漏的测试。

### 视觉验收

在 1440x900、1280x800、390x844 三个视口检查：

- 信息总览、今日研判、A 股观察、首次涨停、量化分析、新闻、可转债和设置页面使用同一色彩和标题语言。
- 无浅色页面残留，也无大面积高亮背景。
- 核心字体可读，中文不被 Orbitron 强制渲染。
- 不出现文字截断、按钮溢出、指标跳动、面板互相遮挡或嵌套卡片。
- 突发、风险、上涨、下跌、实时和不可用状态在各页面含义一致。
- 事件 K 线的标记、索引和详情保持可读，事件多时不互相重叠。

## 实施边界

实施应先建立全站令牌和公共原语，再按页面类型分批迁移。信息总览和今日研判作为第一批视觉基准页，A 股观察和事件 K 线作为突发新闻集成基准页。其他页面只在基准稳定后迁移，避免在多个独立 CSS 系统上继续叠加特例。

对当前已有的未提交修改不做回退。实施计划必须将每个任务限定在明确文件和测试范围内，并在每批迁移后执行中文乱码扫描、相关测试、全量前端测试和生产构建。
