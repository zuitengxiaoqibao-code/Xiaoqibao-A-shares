# 告警与盘后闭环收口设计

## 目标

把已经存在但未形成端到端闭环的监控、Edge TTS、飞书和盘后复盘能力补齐，并把真实数据缺口变成可定位、可修复、可追溯的状态。交付入口仍然只有 Windows 便携 EXE。

## 设计原则

- 外部发送默认关闭；只有用户在 EXE 中显式保存飞书 Webhook 后才允许发送。
- Webhook 使用本机凭据保护保存，API 和界面只返回脱敏提示，日志、报告和记忆不记录密钥。
- 本地告警、TTS 和飞书互相隔离，一个通道失败不隐藏其他通道成功状态。
- 不在后端直接控制系统音频设备。应用常驻前端领取待播告警，调用已有 Edge TTS，播放完成后回写 `sent/failed`。
- 监控运行器订阅现有实时快照总线，不新增第二套行情轮询；只处理已经通过领域校验的快照。
- 盘后报告先冻结事实，再调用 AI，再投递；AI 或飞书失败不能覆盖事实报告。
- `partial/stale/unavailable` 保持真实状态，并携带缺失字段、来源水位和可执行修复动作。

## 组件

1. `NotificationSettingsRepository`：保存飞书启用状态和受保护 Webhook，提供脱敏视图。
2. `FeishuWebhookDelivery`：发送文本卡片，校验 HTTP 状态与飞书业务码，输出稳定中文错误分类。
3. `MonitorRuntime`：订阅 `market_overview/quant_strategy/news_events/late_session_candidates`，执行规则、去重、持久化并独立投递飞书。
4. `GlobalAlertAnnouncer`：常驻 EXE 前端，领取待播告警、调用 Edge TTS、播放并回写投递状态。
5. `PostCloseReportService`：复用同一飞书投递器；调度器在 15:30 执行，启动后对最近应执行交易日补跑一次。
6. 监控中心：规则编辑、飞书配置/测试、通道状态、告警证据和失败原因集中展示。

## 验收

- Mock Webhook 能验证请求体、脱敏存储、成功/超时/HTTP/业务码失败。
- 发布 EXE 在非监控中心页面也能领取待播告警，且不会重复播放。
- 实时总线发布匹配快照后产生一条告警，冷却期内不重复，飞书与 TTS 状态分别落盘。
- 盘后报告重复运行不重复采集事实；失败投递可单独重试；错过 15:30 后启动仍能补跑。
- 未配置外部服务时界面明确显示“未配置”，不显示成功。
- 全量测试、生产构建、乱码扫描、便携 EXE 构建、真实 smoke、恢复演练和发布质量门禁全部通过。
