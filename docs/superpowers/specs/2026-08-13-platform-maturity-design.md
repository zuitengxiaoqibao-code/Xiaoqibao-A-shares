# 一树-A股观测台平台成熟化设计

**日期：** 2026-08-13  
**状态：** 已批准，进入分阶段实施  
**目标：** 在不牺牲真实数据边界的前提下，让已有数据更快、更完整、更容易追溯，并把长期运行、发布和恢复纳入工程治理。

## 1. 问题边界

当前系统已经具备真实通达信/本地数据、同日快照、增量资源、来源健康、字段证据和便携 EXE 能力，但仍有四类系统性风险：

1. 启动和切页的等待缺少统一的 P50/P95 基线，无法区分网络、数据库、解析和渲染耗时。
2. 历史日线覆盖率、缺口、修复前后差异没有形成自动闭环，数据完整性只能靠人工观察。
3. 同一字段多来源冲突、原始快照、解析器版本和展示结论之间的关联不够集中，追溯需要跨文件查找。
4. 便携版的缓存/真实数据/日志/模型边界、数据库迁移和发布回滚虽已有基础，但缺少统一版本契约和质量门禁。

本设计不改变用户交付方式，不把浏览器或 HTML 作为产品入口，不连接券商，不下单，不用随机值、零值或无关字段补齐真实缺失。

## 2. 目标架构

### 2.1 统一证据快照

每个可展示的数据域使用统一的 `SnapshotEnvelope`：

- `snapshot_id`：不可变快照标识；
- `trade_date`、`phase`、`observed_at`、`generated_at`：交易日与采集时间；
- `source`、`source_version`、`parser_version`：来源与处理版本；
- `coverage`、`status`、`missing_fields`、`conflicts`：覆盖、状态、缺失与冲突；
- `content_hash`、`parent_snapshot_id`：内容指纹与增量链路。

前端缓存只复用同一上海交易日且状态可接受的完整快照；后台刷新只提交更新域，迟到、空响应或部分失败不得清空既有完整内容。

### 2.2 性能路径

启动拆成“窗口可见 → API 就绪 → 首屏缓存 → 关键域最新 → 全量验证”五个里程碑。每个请求记录域名、缓存命中、来源、耗时、行数和状态，聚合 P50/P95/P99。页面切换优先读取内存/磁盘同日快照，再由后台增量更新；相同请求使用单飞合并。

验收目标：窗口可见 P95 < 1s，API 健康 P95 < 5s，信息总览有缓存时首屏 P95 < 2s；核心页面切换不触发整页阻塞，单域失败不影响其他域。

### 2.3 历史完整性闭环

建立交易日历、证券集合和日线覆盖的质量检查：缺口按证券/日期/来源分组，优先使用本地通达信导入，必要时进入待修复队列；修复任务记录输入指纹、处理批次、成功/失败计数和前后覆盖率。未达到门槛时，页面明确显示“部分覆盖/待补齐”，不生成策略结论。

### 2.4 追溯与冲突

字段级证据记录原始来源、观察时间、解析版本、内容哈希和选择原因。多来源值不一致时生成冲突记录，展示层显示采用来源与冲突状态，诊断层保留全部候选值。任何研究、量化候选或提醒都引用输入快照 ID 和规则版本。

## 3. 两个工程治理项

### 治理项 A：可观测性与质量门禁

统一结构化运行事件和质量指标：请求耗时、缓存命中率、源健康、覆盖率、冲突数、失败队列、前端渲染耗时、EXE 启动里程碑。CI/发布门禁至少检查 API/Web 测试、乱码、类型检查、构建、数据契约和 smoke；门禁失败不得覆盖正式持久目录。日志脱敏，绝不记录密钥或完整原始行情。

### 治理项 B：可复现发布与数据库迁移/回滚

发布包固定版本、提交、依赖锁文件、迁移版本、数据目录清单和 SHA-256。数据库迁移采用幂等、可检测、可回滚的版本表；发布前创建备份和清单，失败自动恢复程序本体并保留持久数据。缓存、新闻和日志可按策略清理，真实数据和用户配置不可被普通清理操作删除。

## 4. 非目标与安全边界

- 不承诺预测涨跌或将策略评分包装为投资建议。
- 专业通达信接口不可用时保持 `unavailable`，不以普通行情替代。
- 不自动关闭、重启或操控通达信，不控制鼠标或桌面。
- 不通过降低字体、隐藏缺口或伪造进度来制造“已完成”观感。

## 5. 分阶段交付

1. 性能基线、数据域耗时采样和同日快照复用；
2. 历史覆盖率检查、缺口队列和修复对比；
3. 来源冲突、字段证据和研究/量化输入链路；
4. 数据分层、缓存清理、迁移和可复现发布；
5. 全量测试、EXE 重建、真实数据 smoke 和验收报告。
