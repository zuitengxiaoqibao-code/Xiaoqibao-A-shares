# 资金流可靠性设计

## 目标

提高个股资金流在上游连接异常时的可用性，同时保持数据来源、时间和缺失状态可审计。资金流仍是可选观察证据，不改变确定性动作、置信度或风险门禁。

## 方案

- 日级资金流首先请求东方财富 `push2his` 日线端点；连接、5xx、无效 JSON 或空序列时，按顺序回退到同一提供方 `push2` 的 `klt=101` 日线端点。
- 分钟资金流仍请求 `push2` 分钟端点。分钟端点失败不丢弃已经取得的日级序列，而是生成带 `minute_error` 的部分快照。
- 快照保留 `daily_endpoint`、`minute_endpoint` 和 `minute_error`。来源仍统一标记为 `eastmoney-fund-flow`，实际端点写入冻结快照，便于审计和复盘。
- 两个端点都失败时不写入快照；准备状态保持 `partial`，原因保留上游原始错误。

## 诊断与界面

日级可用、分钟级缺失时，诊断分区状态为 `partial`，原因码为 `fund_flow_intraday_unavailable`。新手驾驶舱显示“日级资金流可用，盘中分钟资金流暂未返回；本项仅供历史观察”，不把部分数据伪装成完整实时资金流。

## 验证

覆盖 HTTP 503、连接断开、备用端点成功、分钟端点部分失败、快照完整性、诊断状态、驾驶舱提示和移动端布局；全量后端/前端测试、构建、Ruff、UTF-8 扫描和差异检查作为交付门禁。
