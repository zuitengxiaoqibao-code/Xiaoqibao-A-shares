# 一树-A股观测台性能与维护闭环 v5.0 设计

## 目标

在不改变真实数据边界、不控制通达信、不强制关闭用户正在运行的软件的前提下，完成七项闭环：真实任务进度、API 快速可用、公司研究增量展示、下次启动应用新版、性能仪表盘、完整快照治理、存储与新鲜度治理。

## 设计原则

- EXE 是唯一用户交付入口；localhost 只用于内部诊断。
- 不生成随机、模拟、缺失补零或代理数据。
- 有真实总量才显示百分比；无总量只显示阶段、耗时和动态活动状态。
- 旧的完整快照可继续展示，但必须公开生成时间、数据截止时间和新鲜度。
- 部分成功不能覆盖上一份完整快照。
- 页面切换不触发全市场同步扫描；重型服务按首次使用延迟初始化。
- 更新只在下一次启动前应用，失败自动回滚，持久目录永不参与替换。

## 1. 通用真实任务进度

新增进程内任务登记表，任务状态统一为：`queued/running/succeeded/failed/cancelled`。任务快照字段为：

`task_id`、`kind`、`status`、`stage`、`processed`、`total`、`percent`、`detail`、`started_at`、`updated_at`、`finished_at`、`error`。

只有 `total > 0` 时计算 `percent = processed / total * 100`；否则 `percent=null`。任务完成或失败后保留有限历史，避免内存无限增长。首期使用 HTTP 轮询，不引入 WebSocket。

## 2. API 核心快速启动

启动分为两层：

- 核心层：设置、静态前端、健康检查、基础仓库、缓存读取和页面必需依赖。
- 扩展层：公司研究增强、全市场扫描、专业通达信、Kronos、板块资金采样等首次使用或后台延迟初始化。

核心健康接口必须代表真实可用，不能提前返回假 ready。启动日志记录每个阶段耗时；目标为窗口 3 秒内可见，核心 API 在典型热启动 2 秒内可用，冷启动继续记录真实基线而不伪造承诺。

## 3. 公司研究分块增量展示

公司研究拆分为六个逻辑块：

1. `identity`：代码、名称、日期和基础上下文。
2. `financials`：多年财务和质量指标。
3. `profile`：F10、主营和行业证据。
4. `valuation`：当前估值、同行与机械情景。
5. `events`：新闻、研报、催化和风险。
6. `analysis`：评分、反方审查、证据账本和 AI 解释。

保留原完整接口兼容现有调用；新增任务式分块接口。前端优先展示当日完整缓存，然后逐块替换成功区域。单块失败只标记该块，不清空其他内容。全部块完成后才写入新的完整快照。

## 4. 下次启动自动应用新版

构建或旁路发布产生 `pending-update.json`，记录 staged 目录、目标目录、版本、文件摘要、创建时间和持久目录白名单。桌面入口在创建运行锁和启动 API 前检查清单：

- 校验 staged 路径位于允许目录且核心文件存在。
- 将当前程序文件移动为 rollback 备份。
- 原子替换非持久文件。
- 失败恢复旧版并写日志。
- `config/data/news/cache/logs/models/exports/backups` 只保留，不覆盖、不删除。

运行中绝不强制替换或关闭用户实例。

## 5. 页面性能仪表盘

记录 API 端点与前端页面加载的最近样本：耗时、成功状态、缓存命中、数据源、时间。SQLite 聚合最近 10 次、P50、P95、失败率和缓存命中率。运维页默认折叠展示，突出最慢端点和最慢数据源；指标本身不得阻塞业务请求。

## 6. 完整快照缓存治理

统一快照信封：

`schema_version`、`data_version`、`scope`、`symbol`、`generated_at`、`source_cutoff`、`completeness`、`value`。

`completeness` 只有 `complete/partial`。完整读取必须校验版本、标的、日期和结构。写入使用临时文件加原子替换；前端 localStorage 使用新 key 写成功后再切换索引。partial 只能进入增量缓存，禁止覆盖 complete。

## 7. 存储与数据新鲜度红线

存储页先预览再清理，列出预计文件数和空间。允许清理的范围仅为可重建缓存和过期日志；禁止清理配置、持仓、复盘、策略、核心行情、新闻数据库和模型。新鲜度按数据类别独立配置：盘中行情、市场快照、新闻、财务、研报、历史日线分别判定，状态统一为 `live/fresh/stale/expired/unavailable`，并公开截止时间和原因。

## 错误处理

- 任务失败保留阶段、错误码和最后更新时间。
- 扩展服务初始化失败只影响对应功能，核心 API 继续可用。
- 公司研究单块失败继续显示缓存和其他成功块。
- 更新失败自动回滚，禁止留下半更新目录。
- 性能采样写入失败静默降级并记录日志，不影响业务响应。
- 清理失败按文件记录，但不扩大删除范围。

## 验收

- 新增契约与服务均有 RED→GREEN 自动测试。
- 旧路由与旧缓存兼容测试通过。
- API、Web 全量测试和 production build 通过。
- 中文 UTF-8/乱码扫描与 `git diff --check` 通过。
- 执行便携构建；正式版被占用时只生成 staged 更新并登记下次启动应用。
- 对新 EXE 执行 `run-portable-smoke.ps1 -UseReleaseData`，且只结束烟测自身进程。
