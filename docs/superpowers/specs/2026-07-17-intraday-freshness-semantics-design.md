# 盘中新鲜度语义设计

日期：2026-07-17

## 问题与根因

真实运行态中，盘中建议快照已 437 秒没有语义变化，但焦点行情 8 秒前轮询成功、全域行情 69 秒前轮询成功，轮询状态为 `normal` 且失败计数为 0。前端仍显示“聚合数据已过期”，因为它只比较 `server_time` 与建议快照 `generated_at`。

`generated_at` 表示确定性建议何时发生了可持久化变化；没有价格方向、动作、风险或证据变化时，监控按设计不追加新版本。它不能表示行情链路是否仍在成功工作。

## 方案比较

1. 把提示改成“建议未变化”。无法证明未变化原因，链路中断时也可能误导用户。
2. 后端新增一套计算后的阶段新鲜度字段。语义集中，但会重复现有 `last_focus_success_at`、`last_universe_success_at`、间隔和失败状态，增加不必要的契约。
3. 前端使用现有权威轮询状态计算实时新鲜度。单股使用焦点轮询，全市场使用全域轮询；建议生成时间只在服务刚启动、尚无成功轮询时作为保守回退。

采用方案 3。

## 新鲜度规则

新增纯函数 `livePhaseFreshness`，输入当前阶段、市场状态、服务器时间、阶段生成时间、研判范围和轮询状态，输出 `fresh`、`stale`、`uninitialized` 或 `not_applicable`。

- 只有 `phase === "intraday"` 且 `market_session === "open"` 时检查实时行情。
- 单股范围使用 `last_focus_success_at` 和 `focus_interval_seconds`。
- 全市场范围使用 `last_universe_success_at` 和 `universe_interval_seconds`。
- 有成功轮询时间时，它是唯一新鲜度基准；不能再被旧建议生成时间覆盖。
- 尚无成功轮询时，回退阶段 `generated_at`；两者都不存在则为 `uninitialized`，不编造状态。
- 有效阈值为 `max(stale_after_seconds, relevant_interval_seconds * 2)`，避免在正常轮询刚到期、下一次请求正在执行时瞬时误报。
- 时间格式无效时返回 `uninitialized`，不把解析失败显示成数据中断。
- 盘前、盘后、历史日期和休市状态返回 `not_applicable`，冻结快照不套用盘中实时阈值。

## 展示规则

`fresh`、`uninitialized` 和 `not_applicable` 不显示陈旧横幅。`stale` 显示“行情更新已超过有效时间”，同时注明最近一次焦点或全市场行情成功时间，并说明旧建议会保留但不会用推测数据刷新。

轮询失败或降级仍由阶段栏的 `轮询 degraded`、失败计数和 API 状态表达；本切片不把一次失败等同于数据已经超过有效时间。

## 边界

- 不为了刷新时间戳而制造新的建议版本或调用 AI。
- 不改变轮询频率、退避、行情存储、决策哈希或历史快照。
- 不隐藏真正超过有效阈值的实时数据中断。
- 不恢复模拟交易、资金、订单或自动交易功能。

## 验收

- 建议生成时间很旧但相关轮询刚成功时不显示陈旧横幅。
- 全市场和单股范围分别使用全域与焦点成功时间。
- 相关轮询超过动态阈值时显示明确的行情陈旧横幅和最近成功时间。
- 非盘中阶段、休市和历史日期不显示实时行情陈旧横幅。
- 全量 Web/API 测试、构建、Ruff、编码、差异和真实浏览器检查通过。
