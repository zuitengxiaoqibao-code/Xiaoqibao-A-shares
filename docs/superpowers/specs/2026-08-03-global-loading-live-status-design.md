# 全站加载与实时监控状态设计

## 目标

用户在任何数据请求期间都能明确看到任务仍在运行；请求成功后，缓存进度状态切换成“已加载实时最新数据”和“当前状态：实时监控中”；请求失败时说明失败环节、失败对象和原始原因。

## 状态模型

- 有真实字节长度的请求继续使用 1%–100% 的确定进度。
- 无法测量总量的任务不生成虚假百分比，使用持续移动的动态进度轨道、加载图标和阶段说明。
- 最新数据成功写入缓存后，状态条保留完成轨道，显示绿色实时脉冲、最新更新时间和“实时监控中”。
- 只有当页面仅恢复缓存且尚未完成最新请求时，才显示缓存状态；成功后明确升级为实时最新数据。

## 失败信息

共享刷新状态根据最后一个真实进度阶段展示失败环节：连接、接收、解析或刷新。失败对象使用页面业务名称，例如“公司研究最新数据”。原因保留 API 返回的可读错误，不改写为笼统的“不可用”。已有缓存时继续展示完整内容。

## 全站动态反馈

所有 `aria-busy="true"` 区域获得统一的动态扫描轨道和轻量脉冲，不依赖每个页面自行实现动画。所有 Lucide 加载图标统一旋转。对候选池、搜索、市场情绪、新闻、运维、风险、首次涨停和治理页面中仍未声明 busy 状态的加载容器补齐语义属性。

## 验证

- 共享状态组件测试实时监控成功态与结构化失败态。
- 样式安全测试检查全局 busy 动画和加载图标动画。
- 关键页面测试检查加载容器声明 `aria-busy`。
- 运行前后端全量测试、生产构建、UTF-8/乱码扫描、便携 EXE 重建与实际启动烟测。
