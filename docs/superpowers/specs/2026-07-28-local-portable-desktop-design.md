# 小七宝本地便携桌面版设计

日期：2026-07-28

## 目标

把现有 React + FastAPI 项目转换为 Windows 10/11 可直接运行的本地桌面软件。最终交付物是一个无需安装、无需 Node.js、无需单独启动 API 的便携目录，用户双击 `xiaoqibao.exe` 即可使用。

设计必须同时满足：

- A 股为主要资产域，可转债继续保持独立路由、状态和数据仓储，方便以后增加其他资产域。
- 可由通达信提供的数据优先读取本机通达信文件或通达信行情协议。
- 页面点击不再同步等待整套远程采集和分析；先显示本地快照，再接收增量更新。
- 本地读取和进程内分发尽可能达到毫秒级，网络行情按真实上游能力达到亚秒或秒级。
- 新闻、缓存、日志、模型、导出和配置使用独立目录，缓存可以分类查看和清理。
- 代码按职责拆分，消除大型启动文件、集中样式文件和跨域装配文件。
- 不生成安装程序，不把 Chromium、Node.js、Kronos 权重或开发依赖打进主程序。
- 不因追求速度伪造实时性；任何数据都保留来源、行情时间、抓取时间、质量和陈旧状态。

## 已确认基线

当前工程和本机环境已经完成只读审计：

- 前端生产包约 1.8 MB，可由 FastAPI 直接托管，不需要在成品中携带 Node.js。
- 当前 FastAPI 启动装配集中在 719 行的 `main.py`，并在启动阶段执行证券目录和可转债目录联网同步。
- 当前前端样式集中在约 173 KB 的 `theme.css`。
- 当前盘中关注标的轮询间隔为 60 秒，全局范围轮询间隔为 180 秒，无法满足秒级展示目标。
- 当前 `.runtime` 根目录约 1.24 GB，其中 `a-share-research.sqlite3` 约 1.04 GB，主要来自重复候选快照。
- 本机通达信运行目录为 `D:\new_tdx_mock`，`TdxW.exe` 正在运行，WebView2 运行时已经安装。
- 本机 `vipdoc` 中约有 9,409 个沪深北日线文件，沪市 4,790 个、深市 4,284 个、北交所 335 个。
- 三个样本股票的本地日线包含 2026-07-28 数据；热读取平均约 2.5 ms，首次读取约 3-20 ms。
- 本机 `vipdoc/*/minline` 当前没有分钟线文件，因此盘中分钟、逐笔和盘口不能假设为本地文件可用。
- `T0002/hq_cache` 存在沪深北证券主数据文件，可作为本地证券目录候选来源。

## 非目标

- 不连接券商账户，不下单，不实现自动交易。
- 不承诺交易所直连、Level-2 授权行情或真正的逐毫秒行情。
- 不把远程轮询结果标记为本地实时流。
- 不在本期把所有历史代码重写为新的框架。
- 不把每一条实时行情保存成一个独立文件，避免文件数量失控；“内容对应文件”指代码职责和数据目录清晰分离。
- 不自动删除现有 `.runtime` 或旧数据库。

## 方案选择

### 方案 A：PyInstaller onedir + pywebview/WebView2 + FastAPI

这是采用方案。

- React 构建为静态资源，由同一 FastAPI 进程提供页面和 API。
- `xiaoqibao.exe` 启动本地 API，并使用系统已安装的 WebView2 打开独立桌面窗口。
- PyInstaller 使用 `onedir`，Python 依赖放入 `_internal`，不使用每次启动都临时解压的 `onefile`。
- 用户数据全部位于可执行文件旁的独立目录，不写进 `_internal`。

优点是复用当前业务代码、交付风险最低、无需捆绑浏览器内核、支持便携目录和独立窗口。缺点是仍需携带 Python、Pandas 和 DuckDB 运行库，体积不会像纯原生程序一样小。

### 方案 B：浏览器启动器 EXE

该方案只启动 FastAPI 并调用默认浏览器，体积略小、依赖更少，但不像独立软件，窗口生命周期和浏览器标签页也难以统一管理，因此不采用。

### 方案 C：Tauri + Python sidecar

该方案的桌面外壳较轻，但需要 Rust/Tauri 与 Python 两套构建链，sidecar 生命周期、端口、升级和调试复杂度更高，不能降低现有 Python 数据依赖的主要体积，因此不采用。

## 桌面进程架构

### 1. 启动器

新增 `qibao_desktop` 包，职责按文件拆分：

- `entrypoint.py`：命令行入口和退出码。
- `paths.py`：冻结态、开发态和便携目录解析。
- `instance.py`：单实例锁和已有实例探测。
- `server.py`：预绑定本地端口、启动和停止 Uvicorn。
- `window.py`：创建 pywebview 窗口、关闭回调和浏览器回退错误页。
- `health.py`：启动前置检查和内部健康探测。
- `logging_config.py`：桌面日志、轮转和崩溃记录。

启动顺序：

1. 解析便携根目录并创建缺失的运行目录。
2. 获取单实例锁；已有实例健康时不再启动第二套数据库服务。
3. 预绑定 `127.0.0.1` 的可用端口，避免固定端口冲突和先查后占的竞态。
4. 在后台线程启动单进程 Uvicorn，并等待内部健康接口成功。
5. 使用 WebView2 打开本地 URL。
6. 窗口关闭时停止行情任务、刷新数据库、优雅关闭 Uvicorn 并释放实例锁。

服务只监听 `127.0.0.1`。不开放局域网访问，不申请管理员权限。

### 2. FastAPI 应用工厂

保留 `qibao_api.main:app` 兼容现有测试和开发启动，同时把当前 `main.py` 拆为：

- `bootstrap/app_factory.py`：创建 FastAPI、注册中间件和路由。
- `bootstrap/lifespan.py`：生命周期入口。
- `bootstrap/repositories.py`：仓储创建和关闭。
- `bootstrap/data_sources.py`：数据源装配。
- `bootstrap/services.py`：业务服务装配。
- `bootstrap/background.py`：调度、行情和后台同步任务。
- `bootstrap/static_app.py`：静态资源和 SPA 路由回退。
- `runtime/layout.py`：运行目录模型与初始化。

启动关键路径只允许读取本地配置、打开本地数据库、建立行情内存仓和注册服务。证券目录、可转债目录、新闻和外部来源同步全部移入后台，不能阻塞首屏。

### 3. 前端静态托管

- `/api/*`、`/health` 和 `/ws/*` 继续由 FastAPI 处理。
- `/assets/*` 从 `web/assets` 提供并使用长期缓存头。
- 非 API 的未知路径返回 `web/index.html`，确保现有书签和前进后退不失效。
- API 404 不得回退为 HTML。
- 生产构建使用相对稳定的根路径，开发时继续使用 Vite 代理。

## 通达信本地优先数据架构

### 1. 安装目录发现

新增 `gongbu/tdx_local` 包：

- `discovery.py`：目录发现和候选排序。
- `validation.py`：校验 `TdxW.exe`、`vipdoc` 和 `T0002/hq_cache`。
- `daily_reader.py`：本地日线读取。
- `instrument_reader.py`：沪深北证券主数据读取。
- `watchlist_reader.py`：通达信自选分组只读导入。
- `file_state.py`：文件大小、修改时间和数据日期状态。
- `models.py`：本地数据契约。

发现优先级：

1. 用户在 `config/app.toml` 中显式配置的路径。
2. 当前运行的 `TdxW.exe` 所在目录。
3. Windows 注册表中的安装信息。
4. 常见目录，如 `C:\new_tdx`、`D:\new_tdx` 和当前已发现目录。
5. 上次验证成功的缓存路径。

目录验证失败只会降低通达信本地源状态，不阻止软件启动。

### 2. 只读和并发安全

- 软件绝不修改通达信安装目录中的任何文件。
- 读取前后检查文件大小和修改时间；通达信正在写入时进行短暂重试。
- 日线文件长度必须满足记录边界；尾部不完整记录不进入结果。
- 证券主数据必须通过代码、市场和名称校验后才写入本软件目录。
- 不依赖未经验证的 `~~~day` 或私有内存缓存格式冒充实时行情。

### 3. 数据源路由

| 数据 | 主源 | 回退 | 刷新特征 |
|---|---|---|---|
| A 股证券目录、名称 | 通达信本地 `hq_cache` | 现有东财/巨潮目录 | 启动本地读取，后台每日核验 |
| A 股日线 | 通达信本地 `vipdoc` | 通达信 TCP，再到百度 | 文件变化或盘后同步 |
| 实时报价 | 通达信 TCP 批量快照 | 腾讯行情 | 活跃标的亚秒到秒级 |
| 五档盘口、逐笔成交 | 通达信 TCP | 无授权数据时明确不可用 | 仅当前标的高频刷新 |
| 财务快照、F10 | 通达信 TCP/本地可用文件 | 现有外部来源 | 低频缓存 |
| 新闻 | 东财等联网来源 | 上次成功快照 | 秒级或分钟级，不宣称毫秒级 |
| 公告、研报 | 巨潮、东财等联网来源 | 本地归档 | 低频同步 |
| 可转债 | 独立腾讯/东财适配器 | 独立缓存 | 不与 A 股状态混合 |

通达信桌面客户端本身不是本机行情服务端。`vipdoc` 适合日线和已下载分钟线；实时价格、盘口和逐笔仍需通过通达信 TCP 行情节点获取。页面必须明确区分“本地文件”“通达信网络”和“腾讯回退”。

## 实时行情中心

新增 `gongbu/realtime` 包：

- `quote_hub.py`：内存最新行情、单调序列号和订阅索引。
- `subscription.py`：当前标的、可见列表、自选股和候选池订阅。
- `tdx_quote_source.py`：通达信批量报价。
- `tdx_transaction_source.py`：当前标的逐笔成交。
- `tencent_fallback.py`：报价回退。
- `polling_policy.py`：按会话、订阅层级和失败次数调整频率。
- `quote_worker.py`：后台采集循环。
- `source_health.py`：延迟、连续失败、熔断和恢复。
- `persistence.py`：聚合后异步落盘。

### 订阅层级

- 当前选中股票：目标 500 ms-1 s 获取一次新快照；逐笔只服务当前标的。
- 当前可见列表和自选股：目标 1-2 s。
- 短线、波段和首次涨停候选：目标 2-3 s。
- 市场广度和全市场状态：按通达信批量能力分片，目标 15-30 s 完成一轮。
- 非交易时段：停止高频轮询，只响应显式刷新和盘后任务。

频率是目标值，不是虚假服务承诺。源端限流、网络延迟、股票数量和通达信节点能力会改变实际间隔。连续失败时指数退避，恢复后逐步回到目标频率。

### 内存和落盘

- API 请求只读内存最新行情，不在用户点击时直接访问外部网络。
- 后台采集成功后先原子更新内存，再通知订阅者，再异步聚合落盘。
- 相同内容只更新时间不写历史事件，只有价格、量、盘口或质量状态变化才产生新事件。
- 原始逐笔默认保留最近 5 个交易日；分钟聚合保留更长周期；日线长期保留。
- 落盘队列有上限和降采样策略，磁盘变慢时优先保留最新状态，不阻塞行情采集线程。

### WebSocket 协议

新增 `/ws/v1/quotes`：

- 客户端发送 `subscribe`、`unsubscribe` 和心跳。
- 服务端发送 `snapshot`、`delta`、`source_health` 和心跳。
- 每条行情包含 `symbol`、`sequence`、`observed_at`、`fetched_at`、`source` 和 `quality`。
- 连接建立后立即发送当前缓存快照，随后只发送变化字段。
- 慢客户端只保留每只股票最新增量，不能让无界队列拖垮后台。
- 断线后前端指数退避重连，并用最后序列号恢复；恢复失败则重新取完整快照。

前端把 100 ms 内多条更新合并到一次 React 状态提交，图表使用增量更新，避免高频数据导致整页重渲染。

## 分析和页面响应

单股页面改为两阶段响应：

1. 从内存行情、本地日线和最近分析快照立即返回基础页面。
2. 缺失的财务、新闻、分类、资金流和 AI 解释在后台刷新，完成后通过状态事件或轻量重取更新对应区块。

确定性结论只在其必要证据变化时重新计算。AI 不参与每次行情跳动，只在证据版本发生实质变化或用户显式请求解释时调用。

页面必须显示：

- 当前价格对应的数据时间和抓取时间。
- 当前数据源及是否回退。
- 本地日线最后交易日。
- 分析快照生成时间和是否仍适用于当前行情。
- 缺失证据和后台补全状态。

## 新闻目录

- 每条原始新闻按内容哈希保存为 `news/raw/<provider>/<date>/<hash>.json.gz`。
- 标准化事件、引用、解释和纠错写入 `news/normalized/news.sqlite3`。
- PDF、图片和公告附件按内容哈希写入 `news/attachments`，重复内容只保存一份。
- 数据库保存文件相对路径、来源 URL、发布时间、抓取时间和 SHA-256。
- 新闻是研究数据，不属于缓存；“清理缓存”不得删除新闻。
- 新闻同步采用来源级限流和内容哈希去重，不在每次打开股票时重新抓取全部新闻。

## 缓存和空间治理

新增 `runtime/cache` 包：

- `catalog.py`：定义缓存类别、路径和是否可安全删除。
- `sizing.py`：异步统计文件数和容量。
- `cleanup.py`：分类清理、过期清理和清理结果。
- `retention.py`：容量上限和时间策略。

可清理类别包括报价临时缓存、HTTP 响应、分析中间结果、图片缩略图、失败锁和临时文件。清理操作必须拒绝越过便携根目录，不能跟随目录联接进入外部路径。

默认策略：

- 日志单文件达到 10 MB 轮转，保留 10 个文件和最近 14 天。
- HTTP 缓存按来源设置 TTL，并有总容量上限。
- 临时文件在正常退出时清理，异常退出后在下次启动清理过期项。
- 原始逐笔按交易日保留，分钟和日线使用不同保留周期。
- 模型、新闻、导出、备份和研究数据库永不被缓存清理接口删除。

数据设置页新增空间仪表盘，显示每个目录的容量、文件数、最近更新时间和可否安全清理，并提供分类清理按钮。

## 数据库存储治理

当前候选快照库的重复追加已经造成约 1.04 GB 文件。新实现采用：

- `current_*` 表保存当前可读状态，允许按主键更新。
- `*_events` 表只在规范化内容哈希变化时追加审计事件。
- 行情抓取时间变化但业务内容未变化时不产生新事件。
- 大型重复输入不在同一行保存两份，公共证据通过内容地址引用。
- 为高频表增加日期分区、索引和可配置保留策略。
- SQLite 和 DuckDB 写操作保持单写者，读路径不被远程请求持锁。

现有审计要求继续保留，但审计记录的是实质状态变化，不是每次无变化轮询。

## 旧数据迁移

迁移必须非破坏执行：

1. 检测旧 `.runtime` 并生成文件、大小、时间和校验摘要。
2. 新目录先创建空仓储和迁移清单。
3. 从旧库读取并校验最新有效状态、必要历史事件和业务数据，写入新仓储。
4. 对新仓储执行数量、时间范围和哈希抽样验证。
5. 旧 `.runtime` 保持原位并登记为只读旧档案，不自动删除、不自动复制 1 GB 重复快照。
6. 用户可以在确认新软件稳定后，通过单独的“旧数据归档”工具移动或清理旧目录。

迁移中断后根据清单继续，不能重复写入已完成分区。

## 前端文件拆分

- `theme.css` 拆为设计令牌、全局基础、桌面壳、通用组件和各功能页面样式。
- 每个功能目录拥有自己的组件、样式、API、类型和测试文件。
- 实时连接放在独立 `realtime` 功能目录，不把 WebSocket 生命周期塞进页面组件。
- 页面组件只消费领域状态，不直接拼接行情协议或缓存路径。
- 保留 JetBrains Mono + Orbitron，字体资源继续本地打包，不访问网络字体。

拆分以职责边界为准，不为追求“一文件一个函数”制造大量无意义小文件。

## 配置和密钥

- 普通设置写入 `config/app.toml`，包括通达信路径、刷新目标、保留周期和窗口状态。
- AI 密钥使用当前 Windows 用户的数据保护能力保存到 `config/secrets.dat`，API 永不返回完整密钥。
- 便携目录复制到另一台电脑后，普通配置可继续使用；受保护密钥需要重新录入。
- 日志不得记录密钥、完整 AI 请求体、数据库连接信息或用户本机敏感路径。

## 打包和体积

新增：

- `packaging/xiaoqibao.spec`：PyInstaller onedir 配置。
- `packaging/hooks/`：DuckDB、Pandas、mootdx、FastAPI 和 pywebview 必需的隐藏导入。
- `scripts/build-portable.ps1`：执行测试、前端构建、EXE 构建和产物校验。
- `scripts/run-portable-smoke.ps1`：启动成品并验证健康、API、静态资源和退出。

发布包不包含：

- `node_modules`、源代码测试、开发缓存和现有 `.runtime`。
- Node.js、pnpm、Vite 开发服务器。
- Chromium 或 Electron。
- Kronos 仓库、PyTorch、模型权重和 Hugging Face 缓存。
- 调试符号、源码映射和无关 Python 模块。

Kronos 继续作为可选外部模型，从 `models/` 或用户配置路径按需加载。最终体积以实际构建统计为准，构建报告必须列出总大小和最大的依赖目录。

## 故障处理

- 通达信目录不存在：软件照常启动，显示本地源未配置，并使用允许的回退源。
- 通达信正在写文件：读取重试，仍不稳定则保留上次成功快照并标记陈旧。
- 通达信 TCP 节点失败：节点熔断，切换节点；报价可回退腾讯，盘口和逐笔明确不可用。
- 新闻源失败：保留上次成功新闻和失败时间，不返回空白假装没有新闻。
- WebSocket 断开：页面保留最后行情、显示连接状态并重连。
- 数据库写入繁忙：写队列退避，读缓存仍可用；超过阈值进入只读降级并提示。
- AI 不可用：保留确定性分析，不让 AI 错误阻塞行情和基础页面。
- 桌面窗口启动失败：记录崩溃日志并给出本地健康诊断，不静默退出。

## 性能预算

性能预算用于发现回归，不用于伪造上游服务能力：

- 软件窗口：本地仓储正常时，目标 3 秒内出现可交互首屏。
- 本地日线：热读取单股最近 300 根目标小于 10 ms；首次读取目标小于 50 ms。
- 内存行情读取：单股目标小于 5 ms。
- WebSocket 内部分发：从行情中心更新到服务端发送目标小于 20 ms。
- 前端合并更新：目标每 100 ms 至多提交一次同类界面状态。
- 选股点击：目标 100 ms 内显示缓存骨架和现有快照；新网络行情按来源实际延迟到达。
- 缓存空间统计不得阻塞界面，必须在后台执行并分批返回。

任何性能页面都同时展示 `observed_at` 和 `fetched_at`，不能只用前端动画频率代表数据刷新频率。

## 测试策略

实现遵循测试驱动开发：先写失败测试，确认失败原因，再实现最小代码并运行回归。

### 后端和桌面测试

- 冻结态和开发态路径解析、目录越界保护。
- 单实例、预绑定端口、健康等待和优雅退出。
- FastAPI 静态资源、SPA 回退和 API 404 隔离。
- 通达信目录发现、无效目录、显式配置优先级。
- 本地日线正常文件、尾部不完整、并发变化、沪深北市场路径和陈旧状态。
- 证券主数据和自选分组的校验、去重与回退。
- 行情中心订阅、批量、去重、序列号、慢客户端背压、熔断和恢复。
- WebSocket 初始快照、增量、重连和来源健康。
- 新闻原始文件哈希、索引引用和重复内容去重。
- 缓存容量统计、分类清理、保留目录保护和目录联接防护。
- 旧数据迁移幂等、中断续传、校验失败不切换。
- 候选快照内容未变化时不增长事件表。

### 前端测试

- 软件启动时本地快照先于后台刷新显示。
- WebSocket 连接、断线提示、重连和增量合并。
- 股票切换会取消旧订阅并订阅新股票。
- 数据源、本地/网络、时间和陈旧状态清晰展示。
- 缓存空间仪表盘只允许清理安全类别。
- A 股和可转债选择、订阅和页面状态保持隔离。
- 小屏、双列和桌面布局不因动态数字变化产生溢出或重排。

### 成品验收

- 全量后端测试、Ruff、全量前端测试和生产构建通过。
- PyInstaller 产物在没有 Node.js 开发服务器的情况下启动。
- 成品健康接口、API、静态资源、前进后退和深层书签通过。
- 使用实际便携版服务进行桌面和移动视口截图检查。
- 通达信存在和不存在两种环境均完成启动冒烟。
- 运行中文乱码扫描、`git diff --check` 和构建产物路径扫描。
- 报告 EXE、`_internal`、`web` 和空运行目录的实际大小。

## 实施顺序

1. 建立运行目录模型、桌面入口和静态前端托管。
2. 拆分应用装配，移除启动关键路径中的联网同步。
3. 接入通达信目录发现、本地日线和证券目录。
4. 建立行情中心、后台轮询和 WebSocket 增量推送。
5. 改造单股页面为本地快照优先和后台分区刷新。
6. 分离新闻、缓存、日志、数据和模型目录。
7. 新建紧凑存储并完成非破坏旧数据迁移。
8. 拆分集中样式和大型前端职责文件。
9. 构建 PyInstaller onedir 产物，执行成品冒烟和体积审计。

每一步都保持当前开发启动方式可用，不在中间状态破坏现有 API 路由和书签。

## 验收标准

1. 用户双击 `xiaoqibao.exe` 即可打开独立软件窗口，不需要安装、不需要运行 Node.js 或手动启动 API。
2. 软件关闭后没有残留 API 进程，再次启动不会因端口占用失败。
3. 当前本机通达信目录能被自动识别，日线和证券目录优先使用本地真实文件。
4. 当前股票和可见列表在交易时段获得秒级动态更新，页面显示真实来源与时间。
5. 单股切换先读取内存或本地快照，不再等待新闻、资金流和 AI 全部完成才显示。
6. A 股和可转债保持独立数据域、选择状态和订阅。
7. 新闻、缓存、日志、模型、导出、配置和研究数据分别存放。
8. 用户可以查看并分类清理缓存，且清理操作不能删除新闻、模型、研究数据、导出和备份。
9. 重复候选轮询不再造成数据库无界增长，旧 `.runtime` 不被自动删除。
10. 生产目录不包含 Node.js、Chromium、Kronos 权重、测试代码或现有 1.2 GB 运行数据。
11. 任何缺失、过期或回退数据都明确标记，不用估算值冒充真实行情。
12. 后端、前端、桌面成品冒烟、中文乱码扫描和体积审计全部通过。
