# A 股盘中热点证据接入设计

日期：2026-07-17

## 问题

当前系统已经能读取个股新闻、行业归属、资金流和实时行情，但没有独立的当日强势股题材归因源。盘中建议中的“热点”主要来自新闻词表或个股板块，无法回答“这只股票今天因为什么题材进入市场关注范围”，也无法区分来源事实与 AI 推测。

## 真实接口结论

2026-07-17 对同花顺公开强势股接口完成只读验证：

- 请求路径为 `http://zx.10jqka.com.cn/event/api/getharden/date/{YYYY-MM-DD}/orderby/date/orderway/desc/charset/GBK/`。
- 当日返回 `errocode=0` 和 35 条记录。
- 响应实际是带 UTF-8 BOM 的 JSON，不是路径声明的 GBK；解析器必须优先严格 UTF-8-SIG，失败后才严格尝试 GBK。
- 当前稳定字段只有 `code`、`name`、`reason`、`date`、`id` 和 `market`。接口没有返回价格、成交额或换手率，系统不得补造这些字段。
- `reason` 使用 `+` 分隔人工维护的题材归因，可作为来源标签，但不等于确定性利好或买卖信号。

## 方案

采用独立热点源、共享追加式证据仓库的方案。

`TonghuashunHotspotSource` 负责请求、解码、响应校验和字段标准化。每条有效记录转换为一个来源文章和一个 `market_hotspot` 事件：股票代码是唯一受影响标的，题材归因按 `+` 分割后写入 `themes`，发生时间定义为本次观察时间，而不是伪造盘中首次异动时间。原始行以 UTF-8 JSON 字节完整保存。

`HotspotIngestionService` 复用 `NewsRepository` 的文章、聚类和事件追加写能力。文章和事件 ID 同时包含交易日、股票代码和题材语义哈希；同一快照重复同步必须幂等，题材变化必须追加新版本，不能修改旧事件。

热点使用独立合规功能 `market_hotspots` 和来源 `tonghuashun`。未授权只阻止热点同步，不阻止东方财富新闻、腾讯行情或既有建议。

## 调度与数据流

固定盘中时点 10:30、13:30、14:30 在决策工作流之前同步对应交易日热点。每个时点形成独立运维任务：成功、失败、重试次数和错误码写入现有 `OperationsRepository`。热点失败不阻止简报或确定性决策，但本轮上下文不得假装热点可用。

手动运行盘中阶段时也先尝试一次热点同步。历史补跑可请求对应历史交易日；同一日期和时点成功后不重复访问上游。后台 60 秒行情轮询不触发热点请求，避免无意义高频访问。

已验证热点事件自动进入现有 `RepositoryEvidenceSource`。盘中评估只在事件窗口内、且股票代码匹配时引用；AI 可以解释冻结的题材标签，但不能更改动作、置信度、风险门禁或生成不存在的热点。

## API 与界面

新增 `POST /api/v1/news/hotspots/sync`，可传交易日，默认使用中国时区当天。响应包含获取、插入、聚类和事件数量。授权缺失返回 403，上游或解析失败返回 503，未来日期和非交易日输入返回 422。

新闻热点页增加独立“同步热点”命令。事件时间线把 `market_hotspot` 显示为“题材热点”，显示股票、题材标签、来源时间和证据链接，不显示不存在的价格字段。质量区增加已验证热点数量。热点同步失败只显示热点错误，不清空已加载新闻和历史热点。

数据设置页沿用现有通用合规列表显示“同花顺热点”，用户可单独授权、确认声明或撤销。

## 边界

- A 股为主，可转债不读取热点事件，也不混入 A 股热点榜。
- 不增加账户、资金、仓位、订单、券商连接或自动交易。
- 不把强势股榜解释成买入推荐，不从题材标签推导价格、收益或确定性方向。
- 不让热点同步失败覆盖东方财富新闻状态。
- 不修改历史事件和历史建议。

## 验收

- UTF-8-SIG 与 GBK 响应均能严格解析，损坏文本和错误码会失败。
- 无效代码、空名称、空题材、日期不符和重复记录被明确处理。
- 重复同步幂等，题材变化追加事件，原始快照可审计。
- 未授权热点不影响现有新闻同步。
- 固定盘中时点先同步热点再运行决策，失败独立记录且决策继续。
- API、界面、全量测试、Ruff、生产构建、严格 UTF-8、乱码、差异和真实接口/浏览器检查通过。
