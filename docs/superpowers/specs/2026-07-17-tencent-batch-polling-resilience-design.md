# 腾讯批量行情轮询容错设计

日期：2026-07-17

## 问题与根因

生产盘中轮询当前对每只股票分别发起一次腾讯行情请求。约八只观察标的就会产生八个独立故障点；其中任意一次连接、状态码、GBK 解码、空响应、字段、成交量或截止时间校验失败，整个焦点或全域轮询都会失败，同一轮已经成功取得的行情也会被丢弃。

轮询状态还只有一个全局 `last_error_code`。焦点和全域先后失败时会互相覆盖，决策 API 也没有输出错误原因，前端只能显示英文 `degraded`，新手无法判断是哪个范围、失败几次、旧建议是否仍可参考。

## 真实接口验证

2026-07-17 对腾讯公开接口完成了以下只读验证：

- `q=sh600519,sz000001` 一次返回两条 88 字段行情。
- 返回顺序与请求顺序一致，语句以分号和换行分隔。
- 反转请求顺序后，返回顺序同步反转。
- 在有效代码后追加无效代码时，无效代码不会返回占位内容，而是被直接省略。
- 响应为 GBK，必须严格解码，不能用替换字符掩盖损坏数据。

因此批量响应必须按返回键映射到股票代码，并显式比较请求集合与有效结果集合；不能按数组位置盲配，也不能把缺失项当成零值。

## 方案比较

1. 保留逐股请求，只给每只股票加一次重试。改动最小，但仍保留 N 次请求和 N 个故障机会。
2. 批量请求后允许部分成功。可用率更高，但全域决策可能在用户不知情时使用不完整股票集合。
3. 首次批量请求全部股票，只对缺失或无效股票定向重试一次，重试后仍不完整则整批失败。

采用方案 3。它减少上游请求数，同时保留完整性门禁，符合“不伪造、不悄悄降级”的项目约束。

## 批量请求与解析契约

`TencentPollingMarketFeed.snapshot_many()` 保持原有公开接口，内部改为两阶段获取：

1. 校验代码唯一并执行一次合规数据源检查。
2. 将代码转换为带交易所前缀的 instrument，以逗号连接成一个腾讯请求。
3. 对响应执行 HTTP 状态检查和严格 GBK 解码。
4. 按 `v_<instrument>="<payload>";` 语句解析，建立代码到 payload 的映射。
5. 对每个 payload 独立执行现有价格、昨收、成交量、观察时间和 cutoff 校验。
6. 首轮缺失或校验失败的代码进入一次定向重试；首轮请求整体失败时，全部代码进入这次重试。
7. 重试后仍缺失或无效时抛出 `IncompleteQuoteBatchError`，不得把部分结果标记为成功。
8. 完整成功后按原请求顺序返回快照。

空代码集合不访问上游并返回空元组。重复代码继续拒绝。任何缺失行情都不补零、不复用旧快照冒充本轮新行情。

## 轮询状态与兼容性

`PollState` 新增：

- `focus_error_code`
- `universe_error_code`

保留已有 `last_error_code` 以兼容已持久化事件和内部诊断，但前端不再依赖它做范围归因。

失败时只更新当前范围的错误码和失败计数。某范围成功后只清空该范围错误码；如果另一范围仍失败，整体模式仍为 `degraded`，另一范围的错误原因必须保留。旧数据库事件没有新字段时按 `None` 读取，不猜测历史错误属于哪个范围。

决策 API 在初始化和正常状态下都固定输出两个范围错误字段，值可为 `null`。这避免客户端用字段缺失推断状态。

## 新手界面

只在实时盘中阶段展示与当前观察范围相关的轮询状态：

- 选中单股时读取焦点失败计数和 `focus_error_code`。
- 全市场视图读取全域失败计数和 `universe_error_code`。
- 另一范围降级时，不在当前范围制造误报。
- 当前范围失败时显示中文说明、连续失败次数和旧建议保留规则。
- 常见错误码映射为“上游行情响应超时”“部分股票行情缺失，完整性检查未通过”“行情数据格式不完整”等；未知错误使用保守通用文案，不展示内部异常堆栈。
- 阶段栏用“焦点行情正常 / 焦点行情异常”或“全市场行情正常 / 全市场行情异常”，不再直接显示 `normal`、`degraded`。

行情是否已经超过有效时间仍由既有新鲜度规则独立判断。短暂失败但最近成功数据仍在有效期内时，明确说明系统正在重试；真正超时后继续显示已有的陈旧行情警告。

## 边界

- 不改变确定性策略、建议动作、置信度、风险门禁或 AI 权限。
- 不因轮询状态变化制造新的建议版本或调用 AI。
- 不把部分股票行情当成完整全域输入。
- 不恢复模拟资金、账户、仓位、订单、券商连接或自动交易。
- 本切片只处理 A 股盘中轮询；可转债继续使用独立链路。

## 验收

- 多只股票首轮只发一个批量请求。
- 首轮部分缺失时只重试缺失股票，并在完整后按原顺序返回。
- 重试后仍缺失时整批失败，不持久化部分成功批次。
- 焦点和全域错误码互不覆盖，任一范围恢复不会清空另一范围错误。
- API 输出两个范围错误码。
- 当前范围的异常在盘中显示为中文可读说明，非当前范围异常不误报。
- 全量 API/Web 测试、Ruff、构建、严格 UTF-8、乱码、差异和真实运行检查通过。
