# 个股观察与公司研究当日缓存设计

## 目标

个股观察和公司研究在当天重复进入或重启桌面软件后，立即展示该股票最近一次完整结果，同时后台请求最新真实数据。页面明确显示缓存时间、刷新阶段和进度；最新结果校验并写入缓存后原位替换旧内容。个股观察提供醒目的公司研究入口，并保留当前股票代码。

## 采用方案

使用桌面 WebView 自带的 `localStorage` 保存按功能、交易日和股票代码隔离的 JSON 快照。缓存仅保存真实 API 响应及缓存时间，不生成或补齐业务字段。每个功能最多保留 12 只股票的当天快照，跨日和损坏记录读取时清理。

API 请求使用共享的流式 JSON 读取器。存在 `Content-Length` 时，接收进度按真实字节计算；不存在时只展示已经发生的连接、接收、解析、写入阶段。进度条从 1% 开始，解析完成并成功写入缓存后才到 100%。

## 页面行为

### 个股观察

1. 选择股票后同步读取当天缓存。
2. 命中缓存时立即完整展示驾驶舱，并显示“当前展示 HH:mm:ss 的当日缓存”。
3. 无论是否命中缓存，都后台请求最新驾驶舱数据。
4. 刷新期间保持缓存内容可操作，显示阶段、百分比和“正在载入最新数据”。
5. 成功后更新页面与缓存；失败后保留缓存，明确显示刷新失败原因。
6. 股票标题区增加高亮“公司研究”按钮，打开 `/company-research?symbol=<当前股票>`。

### 公司研究

1. 每个比较池股票分别读取和写入当天缓存。
2. 命中缓存后直接展示完整研究仪表、财务、F10、反方审查和来源账本。
3. 后台刷新不把已缓存条目改为空白加载页。
4. 成功后更新当前条目及同行比较；失败后保留缓存并显示失败状态。
5. 无缓存时显示带真实阶段进度的首次加载面板。

## 错误与边界

- 缓存 JSON 无法解析、股票代码不匹配或日期不是当天时删除并视为未命中。
- `AbortError` 不显示为数据错误。
- 最新请求失败但存在缓存时，不降低缓存内业务状态，只在缓存状态条提示刷新失败。
- 历史 `as_of` 查询按日期单独隔离，不与实时查询互相覆盖。
- 缓存只保存研究响应，不保存 API 密钥、设置、日志或认证信息。

## 测试

- 缓存模块：当天命中、跨日忽略、损坏清理、数量上限。
- 流式请求：有长度的真实字节进度、无长度的阶段进度、错误响应。
- 个股观察：缓存先显示、刷新后替换、失败保留缓存、公司研究跳转。
- 公司研究：缓存先显示、进度提示、刷新替换、失败保留缓存。
- 完整前后端回归、UTF-8/乱码检查、便携 EXE 构建和启动烟测。
