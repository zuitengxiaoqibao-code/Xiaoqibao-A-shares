# 盘中阻断原因贯通设计

## 目标

当盘中确定性评估被阻断时，系统必须记录稳定、可审计的原因码，并在新手 A 股页面解释本轮为何没有新建议。历史建议保持不可变；页面可以保留最近一次可验证判断，但必须明确它不是本轮新生成的建议。

## 后端契约

`IntradayEvaluationResult` 增加默认空元组 `quality_reasons`。确定性评估器按真实门禁生成以下原因码：

- `live_quotes_unavailable`：没有任何当日分层行情。
- `live_quote_quality_blocked`：至少一条行情质量不是 `ready`。
- `live_quote_timestamp_invalid`：至少一条行情时间晚于评估时间。
- `live_quotes_stale`：至少一条行情不满足常规三分钟或午休冻结规则。
- `risk_unavailable`：市场风险输入不可用。
- `compliance_unavailable`：合规输入不可用。
- `compliance_not_allowed`：当前数据来源未通过合规门禁。

原因去重后按上述固定顺序保存。原因不改变动作、置信度、行情值或风险规则；任何阻断结果仍不生成建议。

`IntradayMonitor` 将原因写入 `DecisionCycleSnapshot.quality_reasons`，并把原因加入输入状态哈希。即使同为 `blocked`，原因变化也必须形成新的快照，保证历史可解释。

单股驾驶舱的 `StockPhaseHistory` 增加最新 `phase_status` 和 `quality_reasons`。聚合器只读取截止时间内最后一个阶段快照；没有阶段快照时使用 `empty` 和空原因，不从其他股票或未来快照推断状态。

## 前端行为

`PhaseContextPanel` 导出统一的原因翻译函数。今日研判和详细阶段依据继续使用现有原因列表；A 股三阶段时间线在当前阶段为 `blocked` 时显示醒目说明：本轮数据被拦截、具体原因、下方是否保留最近一次可验证判断。

如果阻断阶段没有该股票的历史建议，只显示阻断说明，不显示“本阶段已运行，当时未纳入这只股票”这类误导文案。未知原因码仍使用现有保守兜底，不推测原因。

## 验证

- 单元测试覆盖无行情、质量异常、未来时间、过期、风险不可用、合规不可用和合规未授权。
- 监控器测试证明原因进入快照并参与状态哈希。
- 前端测试覆盖有旧建议与无旧建议两种阻断页面。
- 全量后端、Ruff、前端、生产构建、UTF-8/乱码扫描和差异检查必须通过。
