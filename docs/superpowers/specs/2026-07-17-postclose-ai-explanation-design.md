# 盘后冻结结果 AI 解释设计

## 目标

让盘后复盘使用已经保存的 OpenAI 兼容设置，对确定性归因和次日观察结论提供新手可读的补充解释。模型不参与结果计算，也不能改变复盘状态、错误归因、撤回条件、次日观察名单、行动、置信度、数值或风险门禁。

## 数据流

盘后服务先按现有规则冻结盘前/盘中建议、收盘结果和审计发现，生成 `AdviceOutcome` 与确定性盘后 `AdviceCard`。只有这些步骤完成后，服务才构造一个 `DecisionAIRequest`：证据包括原建议的冻结证据和每条结果的确定性状态/归因摘要，结论为已经生成的盘后结论。

一次盘后运行最多调用模型一次，不按股票逐条调用。模型返回的摘要追加在每张卡的确定性通俗解释后面；原解释始终保留。AI 元数据和解释身份写入追加式盘后快照，方便审计。

## 状态与幂等

盘后输入哈希加入热加载网关的公开配置身份。保存或切换 AI 配置会在相同冻结结果上追加新盘后快照，旧快照不更新、不删除。

- 有盘后建议且模型输出通过校验：`ai_status=ready`。
- 有盘后建议但未配置、超时、HTTP 错误或输出非法：`ai_status=unavailable`，保留完整确定性解释。
- 没有可复盘建议：不调用模型，`ai_status=not_requested`。

AI 不可用不会把原本完整的盘后数据质量降为 `partial`。阶段 `status` 与 `data_quality` 仍只由收盘结果是否可验证决定。

## 安全边界

复用 `ReloadableDecisionAIGateway` 和 `DecisionAIGateway`，继续拒绝越界证据、数字、价格、评分、仓位和交易计划。API 密钥不进入提示词、返回模型、日志、异常、配置身份或快照哈希。

生产装配让盘前和盘后共享同一个热加载网关与生命周期 `httpx.Client`，避免重复连接池和设置状态分叉。盘中继续由确定性行情规则生成解释，本切片不改变盘中时效和阻断逻辑。

## 验证

测试覆盖 AI 就绪时追加解释、不可用时保留确定性解释、无建议时不调用、配置身份变化追加快照、行动/置信度/归因/次日名单不变、生命周期共享网关。完成后重新运行全部 API 测试、Ruff、全部 Web 测试、生产构建、严格 UTF-8/乱码扫描、`git diff --check` 和真实未配置页面验收。
