# 盘中变化流信息密度设计

日期：2026-07-17

## 问题与证据

真实盘中响应已有 39 个变化版本、72 条变化建议和 444 个支持证据引用。后端每轮把旧盘中行情继续追加到新建议，单条建议最多累积 13 条腾讯行情；前端又把全部版本的 `details` 默认展开。手机端还通过 CSS 把右侧阶段栏排到当前建议之前，导致新手先看到很长的历史流水，而不是当前判断。

## 方案比较

1. 只折叠前端。改动最小，但重复行情仍进入快照、AI 请求和 API 载荷，根因没有解决。
2. 只压缩后端。新快照会变小，但既有不可变历史仍会在界面一次性展开，当前交易日无法立即改善。
3. 后端证据替换与前端渐进披露同时实施。新快照只保留最新行情，既有历史按需查看，且不修改审计记录。

采用方案 3。

## 后端设计

`EvidenceReference` 增加向后兼容的 `evidence_kind`，默认值为 `other`。盘中行情标为 `live_quote`，候选因子标为 `candidate_factor`，核验新闻标为 `verified_news`。旧快照没有该字段时仍可读取。

`DeterministicIntradayEvaluator` 生成下一轮建议时：

- 保留所有不是 `live_quote` 的支持证据。
- 删除上一轮 `live_quote`，追加本轮唯一最新行情。
- 对旧快照使用保守兼容识别：证据 ID 与快照 ID 相同，且以来源名开头时，视为旧格式行情证据。
- 不改变动作、置信度、风险门禁、新闻引用、AI 边界或历史快照。

该规则使每条新盘中建议最多包含一条 `live_quote`，同时保留因子、新闻和其他基线证据。

## 前端设计

盘中变化流按序号从新到旧排列，默认只渲染最近 3 个版本。所有版本详情默认收起，标题保留版本号、变化数量和时间。存在更早版本时显示“查看更早 N 个版本”，展开后仍保持每个版本详情折叠，用户可逐个审计；可以再次收起。

当前盘中建议对旧快照做只读兼容收敛：保留全部非行情基线证据，只展示时间最新的一条盘中行情。被隐藏的旧行情仍完整保存在不可变变化历史中，不从 API 或数据库删除。盘前、盘后建议不应用该收敛。

桌面端继续使用右侧粘性阶段栏。小于等于 760px 时取消阶段栏的首行强制排序，使当前阶段依据和建议先出现，阶段状态与变化历史位于建议之后。顶部质量条已提供当前快照状态，因此不会丢失关键状态。

## 数据与错误边界

- 不删除、不改写任何已存盘中周期。
- 不截断 API 的审计数据，只改变默认渲染数量。
- `change_stream` 缺失或为空时不显示变化流。
- 选股过滤继续在渐进披露前执行，不能泄漏其他股票的变化。
- AI 仍只解释冻结的确定性变化，不生成或修改证据。

## 验收

- 连续两轮盘中评估后，旧行情证据被最新行情替换，非行情证据完整保留。
- 旧格式证据可读取并在下一轮被收敛。
- 五个变化版本默认只渲染最新三个，顺序为新到旧，详情默认收起，展开/收起可用。
- 旧盘中建议的当前视图只显示最新行情和全部非行情基线证据，变化历史仍可查看旧行情。
- 手机端当前判断位于阶段栏之前，无横向溢出；桌面布局保持双栏。
- 全量 API/Web 测试、Ruff、生产构建、严格 UTF-8、乱码扫描、差异检查和真实浏览器检查通过。
