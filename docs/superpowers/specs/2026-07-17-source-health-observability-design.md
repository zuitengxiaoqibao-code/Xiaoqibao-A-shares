# 数据源健康与故障转移可观测性设计

## 目标

把数据源的成功率、耗时、最近成功时间和故障转移事实持久化，让新手能看懂“哪个来源可用、哪个来源失败、是否切换了备用源”。这些统计只描述数据链路，不改变确定性研判、动作、置信度或风险门禁。

## 方案

复用现有 `operations.sqlite3`，增加 append-only 的 `source_attempt_events` 表。每次通达信节点尝试和百度历史批次请求写入一条事件，字段包括来源、操作、节点、状态、耗时、观察时间、错误类型和结构化质量元数据。更新与删除由 SQLite trigger 拒绝，重启后仍可查询。

通达信客户端接收可选的事件回调；每个节点的探测、客户端创建、业务调用、空响应和成功都会在同一操作范围内记录，回调异常被隔离，不阻断行情或基本面请求。百度历史源在严格批次校验成功后记录行数、字段数和最新交易日；HTTP、协议、字段、行宽、重复日期或 OHLC 校验失败均记录为失败后重新抛出。

只读接口 `/api/v1/operations/source-health` 返回按来源和操作聚合的最近事件：状态、尝试数、成功率、平均/最近耗时、最近成功/失败、最后错误、最新交易日、字段数和行数。聚合以最近 20 条事件为窗口，混合成功与失败显示“部分可用”，窗口内无成功显示“不可用”，避免历史旧成功掩盖当前故障。

新手“数据设置”增加来源健康区，默认显示通达信和百度历史源；当没有事件时明确显示“尚未记录”，当百度有事件时额外显示最新交易日与字段校验状态。显示失败原因的友好文案，不展示原始堆栈或秘密信息。

## 不做的事

- 不把成功率转换成买入、卖出、仓位或价格建议。
- 不对东财、新闻或转债新增批量请求；本切片只覆盖已存在的通达信/百度历史链路。
- 不删除现有同步报告、来源授权或运维任务账本。

## 验证

- 仓储测试确认事件 append-only、最近 20 条聚合、状态和成功率计算。
- 通达信测试确认每个节点尝试记录耗时与结果，且观测回调异常不影响返回/故障转移。
- 百度测试确认成功批次记录行数、字段数、最新交易日，坏批次记录失败。
- 路由测试确认返回脱敏的来源健康数据。
- Web 测试确认无事件、健康、部分可用和不可用四种展示状态。
- 全量 API/Web 测试、Ruff、生产构建、严格 UTF-8、乱码扫描、`git diff --check` 和真实浏览器验收通过。
