# 可转债独立玻璃工作台设计规格

日期：2026-07-27

## 目标

将现有可转债专区重构为独立的深色玻璃工作台，并把全站字体统一为 Orbitron、JetBrains Mono 与可靠的中文回退字体。新界面借鉴参考图的空间层次、玻璃材质、翡翠绿高亮和中央任务流，但不复制参考图的品牌、文字或无关业务功能。

可转债继续使用独立入口、独立路由、独立选择状态和独立数据语义，不与 A 股候选、自选或研判状态混合。

## 设计原则

1. 信息先于装饰：每个高亮、颜色和层级都必须表达数据状态或操作焦点。
2. 真实数据优先：缺失、陈旧、冲突或未授权数据必须明确标示，不生成占位数字或模拟图表。
3. 新手可理解：专业指标保留原名，同时提供简短的中文解释和下一步指引。
4. 资产域隔离：所有转债状态、筛选、诊断和关联正股信息只存在于转债专区。
5. 克制的未来感：动画用于聚焦和状态变化，不持续干扰阅读，并支持减少动态效果设置。

## 全站字体规范

全站采用以下字体角色：

- 展示标题、导航分组、英文眉题：`Orbitron`。
- 正文、数字、表格、输入框、按钮和状态文本：`JetBrains Mono`。
- 中文缺字回退：`Microsoft YaHei UI`、`Microsoft YaHei`、系统无衬线字体。

CSS 字体族必须显式包含中文回退，不能强制使用不含中文字形的字体。Orbitron 只用于短标题，不用于长段中文正文。数字采用等宽字体，确保卡片和表格列稳定对齐。

## 视觉系统

### 色彩

- Obsidian：`#050807`，页面底色。
- Glass：`rgba(14, 20, 19, 0.78)`，主要玻璃卡片。
- Silver Line：`rgba(207, 222, 218, 0.16)`，边缘和分隔线。
- Emerald：`#18E985`，当前焦点、可观察和成功状态。
- Amber：`#F0B85A`，待核验、陈旧和仅观察状态。
- Signal Red：`#FF5B67`，风险排除、冲突和错误状态。
- Text Silver：`#D8E1DE`，主要文字。
- Muted Steel：`#74827E`，辅助说明。

### 材质与效果

页面背景使用接近纯黑的径向渐变和极轻微网格。卡片使用低透明度玻璃背景、细银灰边缘和内侧高光。翡翠绿只出现在当前选择、可观察状态和关键主操作上。扫描线和辉光必须克制，不能降低文字对比度。

悬停时卡片边缘略微提亮；键盘焦点使用清晰的绿色双层轮廓。所有动画在 `prefers-reduced-motion: reduce` 下关闭。

## 信息架构

现有全站左侧导航保持不变。可转债专区内部继续提供三个视图：

1. 总览：展示市场覆盖、状态分布和需要处理的转债任务。
2. 诊断：输入或选择一只转债，查看完整证据、风险结论和关联正股上下文。
3. 候选池：筛选、批量诊断并查看可观察、未诊断、数据不可用和风险排除的转债。

三个视图共享同一套工作台外壳和当前转债上下文，但不把未诊断转债伪装成候选。

## 桌面端布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 可转债专区 / 数据状态                         总览 诊断 候选池 │
├──────────────────────────────────────────────────────────────────┤
│ 已发现 │ 可观察 │ 未诊断 │ 数据不可用 │ 风险排除              │
├──────────────┬───────────────────────────────┬───────────────────┤
│ 任务与筛选   │ 中央转债任务流                │ 智能诊断详情      │
│ 状态分组     │ 层叠卡片 / 当前转债高亮       │ 结论 / 风险       │
│ 快速搜索     │ 候选进度 / 证据时间轴         │ 条款 / 关联正股   │
│ 批量诊断     │                               │ 来源 / 下一步     │
└──────────────┴───────────────────────────────┴───────────────────┘
```

顶部统计卡来自 `BondDashboard` 和候选覆盖数据。中央层叠卡片是页面的标志性视觉：每张卡表示一只真实发现的转债，当前卡使用翡翠绿，其他卡使用半透明银灰。卡片至少显示代码、名称和状态，不显示未验证的价格或分数。

右侧详情只展示当前选择的真实诊断结果。未诊断时显示需要执行的核验步骤；数据不可用时显示具体原因和修复入口；风险排除时优先显示风险原因。

## 各视图内容

### 总览

总览默认打开。顶部统计卡展示已发现、可观察、未诊断、数据不可用和风险排除数量。中央任务流按状态组织真实发现池，并优先展示需要处理的未诊断项目。右侧显示当前任务说明、来源覆盖和新手下一步。

若发现池为空，中央区域显示数据源状态和“前往数据设置”的可执行指引，不显示空的装饰性卡片。

### 诊断

左侧提供六位转债代码输入和诊断操作。中央展示当前转债身份、关联正股、关键估值和条款证据。右侧按以下顺序展示：

1. 风险结论：可观察、仅观察或排除。
2. 关键风险：强赎、到期、规模、流动性、来源冲突。
3. 核心指标：转股价值、转股溢价率、纯债溢价、成交额。
4. 证据来源和时间。
5. 面向新手的含义和下一步。

缺少纯债价值、成交额或条款时继续显示“未知”及原因，不推导替代值。

### 候选池

左侧保留最高转股溢价率、最低成交额、最低剩余规模和最低到期天数筛选器，以及“应用筛选”和“诊断首批”。中央任务流展示筛选结果和所有发现项目的状态。右侧展示当前转债的筛选通过项、失败项和证据完整度。

“可观察”与“风险排除”必须视觉分离；“数据不可用”不能计入风险排除；“未诊断”不能计入可观察。

## 状态与颜色语义

- 可观察 / 数据完整：翡翠绿。
- 仅观察 / 行情陈旧 / 待核验：琥珀色。
- 风险排除 / 数据冲突 / 请求失败：红色。
- 未诊断 / 无选择：银灰色。

颜色不是唯一提示。所有状态同时显示可读文字和图标，满足色觉差异用户的识别需求。

## 数据流与状态隔离

保留现有加载接口：

- `loadDashboard` 加载转债覆盖总览。
- `loadDiagnosis` 加载单只转债诊断。
- `loadCandidates` 加载筛选结果与发现池。
- `diagnoseDiscovered` 执行有上限的批量诊断。

视图重构不改变后端契约。选择发现池项目后切换到诊断视图并请求该代码。旧请求晚于新请求返回时不得覆盖当前选择。单个面板加载失败不能清除其他已经核验的数据。

可转债代码不写入 A 股的 `symbol` 选择状态，也不进入 A 股自选或候选列表。

## 空态与错误处理

- 总览失败：保留页面外壳，显示来源级错误和重试方向。
- 单只诊断失败：保留当前代码和已验证的总览数据，只在诊断详情显示失败。
- 候选加载失败：保留筛选条件，允许直接重试。
- 来源未授权：显示“打开数据设置”操作。
- 数据陈旧：显示观测时间，使用琥珀色，不把陈旧行情标成实时。
- 来源冲突：使用红色，明确阻止可观察结论。

## 响应式行为

- 宽屏：左侧任务区、中央任务流、右侧详情三列布局。
- 中屏：顶部统计卡换行，右侧详情移到中央任务流下方，形成两列。
- 小屏：所有区域单列；层叠卡片变为可滚动的横向卡片列表；筛选器逐项排列；主要操作保持至少 44 像素触控高度。

移动端不使用依赖悬停的交互。长数字和来源文本允许换行，不产生横向页面溢出。

## 可访问性

- 三个内部视图继续使用 `tablist`、`tab` 和 `aria-selected`。
- 中央任务卡使用真实按钮，并有包含代码、名称和状态的可访问名称。
- 加载状态使用 `aria-busy`，错误使用 `role="alert"`，批量结果使用 `role="status"`。
- 文本与背景满足清晰对比度；键盘焦点始终可见。

## 测试与验收

### 组件测试

1. 默认打开总览并展示五类真实统计。
2. 三个视图切换后保持统一工作台外壳。
3. 点击层叠任务卡会用对应转债代码加载诊断。
4. 陈旧、冲突、未授权、缺失数据和风险排除使用正确文字语义。
5. 未验证字段不显示模拟数字。
6. A 股选择状态不受转债选择影响。

### 视觉与构建验收

1. 桌面端呈现三列玻璃工作台，中央层叠任务流是唯一主要视觉焦点。
2. 800 像素以下转换为合理单列或双列，520 像素以下为单列。
3. 全站标题、正文、数字和控件符合字体角色规范，中文无缺字或乱码。
4. 运行前端完整测试和生产构建。
5. 对中文相关文件执行乱码扫描和 `git diff --check`。

## 明确不做

- 不复制参考图中的品牌、项目名称、成员、日期或其他业务文字。
- 不加入模拟账户、模拟资金、券商连接或自动下单。
- 不新增没有真实来源支撑的图表、收益率、评分或 AI 结论。
- 不把 A 股候选、市场情绪或首次涨停规则混入转债专区。
- 本阶段不修改后端数据契约或引入新的转债预测模型。
