# Kronos 信号共识与风险缩放设计

## 目标

把量化分析页从“展示若干指标和一条 Kronos 预测”升级为可复核的机械式辅助决策系统：每个独立信号家族只投 `做多(+1)`、`中性(0)` 或 `做空(-1)` 一票，系统按票差计算风险预算，再经过 A 股交易约束、数据质量和波动率缩放，给出观察仓位参考。

系统不承诺收益，不把外部案例中的“1 万美元变 25 万美元”或“Alpha +2362%”当成本项目结果。任何收益、胜率、赔率和 Alpha 必须由本项目的冻结数据、策略版本和样本外回测实际计算。

## 采用方案

采用“固定信号家族等权投票 + 硬风控 + 波动率缩放 + 样本外验证”。

- 不采用简单堆叠大量技术指标。高度相关的均线、MACD 和趋势指标会造成重复计票。
- 不在第一阶段开放任意自然语言生成 Python 策略。后续只允许 AI 把自然语言转换成受控、可验证、可版本化的策略 DSL。
- Kronos 是价格路径信号之一，不是最终裁判，也不能绕过风险门。
- AI 只能解释已经计算出的票数、证据和限制，不能修改票值、仓位或回测结果。

## 核心公式

固定注册 `J = 8` 个信号家族。每个家族在时点 `t` 输出：

```text
s_j(t) in {-1, 0, +1}

-1 = 反对持有该股票
 0 = 中性，或证据不可用
+1 = 支持持有该股票
```

原始共识与投票风险预算严格使用：

```text
C(t)      = (1 / J) * sum(s_j(t))
R_vote(t) = R_max * C(t)
```

其中 `R_max` 默认是计划可投资资金的 `10%`，代表单只股票的最大参考风险预算，不代表满仓全部资金。八票全部赞成时只用满这个受限预算。

缺失信号按 `0` 进入公式，但必须显示为“不可用”，不能伪装成真正的中性判断。另行计算：

```text
coverage(t) = available_signal_count / J
```

当覆盖率低于 `75%` 时，只展示票数，不给非零仓位参考。

波动率缩放与只做多约束：

```text
V(t)     = min(1, 20% / max(realized_vol_20d(t), 10%))
P_long(t)= max(0, R_vote(t))
P_ref(t) = min(10%, P_long(t) * V(t))
```

任一硬风控命中时 `P_ref(t) = 0`。负共识只表示“减仓或不参与”的强度，不生成融券卖空、期货或杠杆指令。

## 八个信号家族

所有阈值写入版本化策略 `consensus-v1`，响应必须返回策略版本和输入快照哈希。

| 信号 | 做多 `+1` | 做空 `-1` | 中性 `0` |
|---|---|---|---|
| Kronos 路径 | 20 日中位收益不低于 `+2%`、下行概率不高于 `45%`、路径分歧不高于 `20%` | 中位收益不高于 `-2%`，或下行概率不低于 `60%` | 其余；模型不可用也记 0，但状态为不可用 |
| 趋势结构 | `close > MA20 > MA60` 且 MA20 五日斜率为正 | `close < MA20 < MA60` 且 MA20 五日斜率为负 | 其余 |
| 动量 | 20 日收益在 `+2%` 到 `+25%` 且 5 日收益为正 | 20 日收益低于 `-5%`，或 5 日收益低于 `-8%` | 其余 |
| 相对强弱 | 股票 20 日收益减沪深 300 同期收益不低于 `+5%` | 差值不高于 `-5%` | 其余或基准缺失 |
| 量价确认 | 当日上涨，且成交量为 20 日均量的 `1.2` 到 `3.0` 倍 | 当日下跌，且量比不低于 `1.2` | 其余；量比高于 3 只加风险提示，不追加强票 |
| 首次涨停结构 | 回撤 `5%-20%`、周/月线均在底部、盘整至少 5 日、`0 < PE <= 50` | 阶段为风险扩大，或 PE 非正/高于 50 | 涨停当日、等待回撤或证据不足 |
| 市场情绪 | 指数 `60 <= score < 80`，且数据当日有效 | 指数低于 `40` | `40-60`、不低于 `80` 或数据不完整；过热另加风险提示 |
| 主力资金 | 5 日和 20 日主力净流入均为正 | 5 日和 20 日主力净流入均为负 | 方向分裂或数据不可用 |

同一信号家族内部可以使用多个原始因子，但最终只能投一票。新增因子前必须说明它属于哪个家族；同类因子不能靠增加数量放大投票权。

## 硬风控

以下条件只负责阻止仓位，不参加票数竞争：

- 涨停当日禁止买入。
- 股票停牌、退市整理、无法确认交易状态或报价过期。
- 日线少于 120 根，或最近有效日线晚于研究截止日。
- 首次涨停策略中 `PE <= 0` 或 `PE > 50`。
- 已验证的重大退市、立案、财务造假或交易限制风险。
- 可用信号少于 6 个。
- 当前策略版本没有达到样本外最低门槛：至少 20 笔闭合交易、样本外 EV 大于 0、最大回撤不高于 25%。

新闻 AI 的正面描述不能解除硬风控。新闻只有在来源、发布时间、标的关联和事件分类均已验证时，才可形成风险拦截；普通情绪性报道不投票。

## 后端边界

新增独立 `quant_consensus` 领域，不把逻辑继续塞进 `kronos_forecast.py` 或前端 `metrics.ts`。

```text
本地日线 / 实时快照 / 情绪 / 资金流 / 首次涨停 / Kronos
                          |
                          v
              QuantSignalInputBuilder
                          |
                          v
             8 个独立 SignalEvaluator
                          |
                          v
                ConsensusVoteEngine
                          |
               +----------+----------+
               |                     |
               v                     v
        PositionRiskScaler     Append-only Snapshot
               |                     |
               +----------+----------+
                          v
 GET /api/v1/a-shares/quant-analysis/{symbol}/consensus
```

API 响应至少包含：

- `status`: `ready | partial | blocked`。
- `symbol`、`as_of`、`observed_at`、`policy_version`、`input_snapshot_hash`。
- 固定信号数、可用数、做多/做空/中性/不可用票数。
- `consensus`、`vote_risk_percent`、`volatility_scale`、`reference_position_percent`。
- 每一票的 `signal_id`、家族名称、票值、状态、证据值、理由码、来源快照和数据时间。
- 硬风控、警告和样本外验证状态。

相同标的、截止时间、策略版本和输入快照必须得到相同票数。Kronos 多路径推理需要保存实际预测摘要与模型版本；回看历史时读取冻结快照，不重新生成一条不同路径冒充原结果。

## 回测设计

新增 `consensus_vote_v1` 回测，不再用现有 `sma_cross` 的结果代表这套投票策略。

- 每个交易日收盘后只使用当时已经可见的数据计算投票。
- 调仓只能在下一个可交易日执行，避免未来数据泄漏。
- A 股只做多，按 100 股整数手，执行 T+1，计手续费、印花税、滑点、涨跌停和停牌无法成交。
- 目标仓位随票差变化，不把每次信号当成全仓买卖。
- 训练、验证、样本外按时间顺序拆分；前两个区间只能用于选定固定阈值，样本外不得继续调参。
- 同时展示总收益、年化收益、Alpha、最大回撤、波动率、胜率、赔率、EV、换手、成本、未成交次数和牛熊震荡分段。
- 样本外闭合交易少于 20 笔时标记“样本不足”，不能显示“已验证”。
- Alpha 使用同期沪深 300 含同样日期区间的收益作基准，并明确计算区间；缺少基准数据时不显示 Alpha。

回测中的初始金额只是计算股票手数和成本所需的标准化名义本金，界面以净值和百分比展示，不恢复“模拟资金账户”。

## 前端设计

量化分析页保留现有四象限和 Kronos 面板，并新增一个横跨全宽的“共识投票台”：

- 顶部中心显示 `赞成票 / 反对票 / 中性票 / 不可用票` 和票差。
- 主仪表显示 `C(t)`，旁边依次展示 `R_max`、波动率缩放、最终参考仓位。
- 八行票据逐项显示票值、证据、数据时间和来源；点击展开原始证据，不显示无法追溯的结论。
- 硬风控使用高亮红色并固定在仓位旁；数据不足使用琥珀色；有效做多共识使用青绿色；Kronos 路径继续使用金色。
- 新手文案固定解释“八票全赞成 = 用满单票风险预算，不等于全部资金满仓”。
- AI 解释单独标识为“文字解释”，并显示“不会改变投票与仓位”。AI 不可用时，机械计算结果仍完整显示。

## 自然语言策略扩展

后续 `consensus-v2` 可以增加受控的自然语言策略编辑器，但不允许 `eval`、任意 Python 或联网下载代码：

1. AI 把中文描述转换成白名单 JSON DSL。
2. JSON Schema 只允许已注册因子、比较运算、时间窗口、投票值和阈值范围。
3. 系统展示生成后的每条规则、数据需求和公式哈希。
4. 规则必须完成回放、样本外回测和风险审核后才能启用。
5. 每次修改产生新版本，旧快照继续绑定旧版本。

“500+ 因子”是扩展能力，不是第一阶段目标。优先保证八个信号家族数据真实、互不重复、可追溯。

## 验收标准

- 固定输入下票值、票数、共识和仓位完全可复现。
- 缺失信号不会伪装成有效中性；覆盖不足时仓位为 0。
- Kronos 不可用时其余信号仍计算，页面明确少一票。
- 任一硬风控可把参考仓位归零，但不得篡改原始票数。
- 全票赞成且无风险时，参考仓位不超过 10%。
- 负票差不产生卖空、期货、杠杆或自动下单指令。
- 共识回测满足时间隔离、交易约束和费用要求；样本不足时不输出“已验证”。
- 前端不出现随机数、`NaN`、`Infinity` 或无法追溯的数据。
- API、前端、生产构建、中文乱码扫描和便携 EXE 冒烟通过。
