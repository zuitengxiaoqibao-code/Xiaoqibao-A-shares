# 公司研究：未来催化与最新提示证据摘要工作台

## 背景

公司研究页面当前直接把通达信 F10 的“最新提示”长字符串铺在卡片内。原文包含日期、公告类型、财务字段和分隔符，导致信息密度失控；“未来催化”维度又重复引用同一段文本，用户无法快速判断事件的性质、时间和影响。

## 目标

- 在不伪造数据的前提下，把 F10 原文整理成可扫描的事件摘要。
- 让“未来催化”只承担结论摘要，让“最新提示”承担分类证据展示。
- 保留来源、观察时间和原始文本，任何摘要都能回溯。
- 在桌面端提高信息层级和字号，并保持小屏可读。

## 方案选择

### 方案 A（采用）

后端对 F10 最新提示做确定性解析，输出结构化事件；前端展示摘要、分类卡片、性质标签和可展开原文。优点是数据语义稳定、测试可覆盖、未来可接入其他公告源；代价是需要扩展 API 合约和测试。

### 方案 B

只在前端切割现有字符串。改动较小，但不同通达信节点返回格式变化时容易失效，也无法让其他消费者复用解析结果。

### 方案 C

只做字体、换行和折叠。视觉改善有限，仍然无法区分公告、业绩和风险。

## 数据契约

在 `CompanyProfileEvidence` 中增加 `latest_tip_items`。每项包含：

- `id`：稳定哈希标识
- `category`：`公告与合同`、`业绩预告`、`资金与融资`、`交易异动`、`风险提醒`、`其他`
- `title`：确定性提取的短标题
- `date`：可解析日期，无则为空
- `tone`：`positive`、`neutral`、`risk`、`unknown`
- `summary`：从原文截取并规范化的 1～2 行摘要
- `source`、`observed_at`
- `raw_text`：该事件对应的原始证据

解析规则只使用原文中的显式日期、关键词和数字，不调用模型臆测事件影响。无法可靠拆分的片段进入 `其他 / 原文待整理`，保留完整原文。

## 页面设计

### 未来催化维度

维度行显示：

- 事件数量，例如“已识别 3 项事件”
- 性质计数，例如“催化 1 · 中性 1 · 风险 1”
- 若无可核验事件，显示“无可核验催化证据”，不重复铺原文

该维度继续标记为不可评分，避免把文本事件误当成量化分数。

### 催化与最新提示卡

新增全宽证据卡，位于财务趋势和反方审查之后、来源账本之前：

1. 顶部摘要条：事件总数、最近日期、风险事件数、来源和观察时间。
2. 分类筛选标签：全部、公告与合同、业绩预告、资金与融资、交易异动、风险提醒、其他。
3. 事件卡片网格：桌面端 2～3 列，小屏单列；每张卡显示日期、标题、摘要、性质标签和来源。
4. 卡片内使用 `details/summary` 展开“查看原始证据”，默认不显示长文本。
5. 页面保留原始 F10 三段资料，但“最新提示”改为折叠原文入口，避免与新卡片重复。

### 视觉层级

- 正文最小字号 14px，事件标题 15～16px，日期和来源 12～13px。
- `positive` 使用市场上涨色，`risk` 使用高亮警示色，`neutral` 使用状态色，`unknown` 使用次级文字色。
- 事件卡片使用左侧色条和轻量 hover 边框，不增加无意义装饰。
- 保持现有终端深色主题、JetBrains Mono/Orbitron 字体和响应式栅格。

## 数据流与错误处理

1. 通达信 F10 返回原文。
2. API 清洗、拆段、分类、提取日期并生成 `latest_tip_items`。
3. 前端只负责筛选、布局和展开原文，不重新解释数据。
4. F10 不可用时显示明确的“通达信 F10 未返回最新提示”；解析失败时显示“原文待整理”，不隐藏原文。
5. 事件摘要旁保留来源和观察时间，缓存与刷新状态沿用现有研究页面机制。

## 测试与验收

- API：覆盖日期提取、分类、风险/中性/催化标签、无法解析片段保留原文、空数据状态。
- Web：覆盖摘要计数、分类筛选、事件卡片、原文展开、无数据提示和字号相关结构类名。
- 完成前执行前端/API 全量测试、UTF-8 严格解码与乱码扫描。
- 用户可见改动后执行 `scripts/build-portable.ps1`，并用 `scripts/run-portable-smoke.ps1` 验证实际 EXE 启动。
- 重建时保留 `config`、`data`、`news`、`cache`、`logs`、`models`、`exports`、`backups`。
