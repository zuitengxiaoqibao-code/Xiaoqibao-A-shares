# 监控中心升级设计

**日期：** 2026-08-24

## 目标

将监控中心从“单条字段阈值 + 告警历史”升级为全项目运行控制台。首屏需要同时回答监控服务是否运行、行情和数据源是否健康、当前有哪些风险告警、投递是否完成，以及告警是否已经恢复。

## 范围

覆盖市场总览、个股观察/自选股、量化策略与候选池、尾盘选股、新闻热点、公司研究风险、数据源与任务健康七类主题。保留现有本地持久化、实时快照总线、Edge TTS 和飞书适配，不引入外部服务，不复制外部项目代码。

## 架构

### 后端

- `MonitorCenterService` 继续负责规则存储、条件匹配和告警审计，新增严重级别、确认状态、恢复状态、连续触发计数和最近触发时间。
- 新增监控摘要读取能力，一次返回服务心跳、规则统计、主题健康、告警统计、待投递队列和最近告警，供首页首屏使用。
- 告警身份由规则、标的、主题和输入哈希组成；同一输入在冷却窗口内不重复生成。
- 当输入不再满足规则时生成恢复记录；恢复不重复调用 AI 或重新采集行情。
- 站内、TTS、飞书投递继续独立记录状态和失败原因；失败重试只重试对应通道。
- 监控摘要中的数据状态使用 `live`、`cached`、`partial`、`unavailable`，不把缺失字段或空响应标为正常。

### 前端

- 监控中心首屏使用紧凑仪表盘：服务状态、心跳与延迟、严重告警、待确认、投递失败、数据源异常。
- 按主题显示健康卡片，直接展示状态、最新时间、告警数量和快捷入口。
- 告警时间线支持严重级别、主题、标的筛选；告警卡片显示股票名称、代码、触发值、阈值、来源、观测时间、失效条件和跳转入口。
- 规则区支持搜索、启停、编辑、复制、删除和批量启停；已有规则格式保持兼容。
- 页面刷新失败保留上一次有效摘要，显示中文失败原因；实时总线增量到达时只更新受影响区域。
- 窄屏自动单列，保持内容紧凑，不产生无意义留白。

## 数据流

1. 实时快照总线发布经过验证的市场、量化、新闻、尾盘和健康事件。
2. `MonitorRuntime` 调用规则评估器，写入触发或恢复审计记录。
3. 摘要接口从持久化记录和当前运行状态生成首屏快照。
4. 前端首屏读取摘要，随后订阅增量告警；断线时以摘要接口轮询保底。
5. 投递队列按通道独立更新状态，失败原因和重试次数可追溯。

## 错误和边界

- 服务未启动、数据源未配置、数据缓存过期、AI 未配置、网络超时分别显示中文状态，不使用模拟行情。
- 部分主题没有数据时保留主题卡片，显示 `部分可用` 或 `暂无可验证数据`，不隐藏整个仪表盘。
- 告警记录只引用真实快照和来源，不在监控中心生成交易建议或虚构概率。
- 规则字段路径不存在时规则不触发，并在规则状态中显示字段不可用原因。

## 测试和验收

- 后端覆盖摘要、主题健康、告警确认、恢复事件、冷却去重、独立投递失败和兼容旧规则。
- 前端覆盖首屏摘要、健康卡片、筛选、启停、恢复告警和失败回退。
- 运行 API 全量测试、Web 全量测试、Ruff、Vite 构建、乱码扫描和 `git diff --check`。
- 运行便携 EXE 构建、真实 EXE 冒烟、14 菜单性能门禁、恢复演练和发布质量门禁。
