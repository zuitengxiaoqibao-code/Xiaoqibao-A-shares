# 信息总览密度与分区恢复设计

## 目标

修复信息总览工作区的大量留白、短卡被长卡拉高、空数据仍渲染大画布，以及单个请求超时导致页面看似卡死或清空的问题。用户始终看到可解释的真实内容：最新成功快照优先，刷新失败时保留上一次完整快照并显示紧凑中文状态。

## 设计决策

### 1. 紧凑栅格

- `distinct-block-grid` 使用 `align-items: start` 和 `grid-auto-rows: min-content`，块高度由自身内容决定。
- `distinct-block` 不再强制 `height: 100%`；只有明确的图表、主表通过组件自身设置高度。
- `size-wide`、`size-half`、`size-third` 继续保持一级菜单平铺，不新增菜单分级。
- 指标卡使用 `minmax(72px, auto)` 的最小高度，标题、数值、口径横向可读；禁止窄列把标题逐字竖排。
- 盘中异动的图表、异动、资讯三栏在桌面端保持紧凑可见，列表使用 `max-height` 而不是固定高度；没有内容的列表使用短空态。

### 2. 空态与证据图

- `distinct-empty` 最大高度约 104px，说明、原因、数据源和重试入口在同一紧凑区域内。
- `evidence-map` 只在有有效节点/边时渲染关系画布；无有效关系时使用 `distinct-empty`，不保留 300px 空画布。
- 空态不把“没有真实数据”伪装成 0，也不填充示例股票、新闻或概率。

### 3. 区块级加载恢复

- 页面已有的 last-good 数据继续作为首屏内容；刷新期间只显示区块级 `refreshing` 状态。
- 区块刷新失败时不清空该区块，不覆盖其它成功区块；错误条显示中文的“阶段、来源、耗时”，提供一次“重试本区块”按钮。
- 状态语义固定为：`ready`、`refreshing`、`stale`、`partial`、`unavailable`、`error`。
- 失败的空响应不能替代已有非空快照；没有任何快照时才显示紧凑错误空态。

## 验收标准

1. 桌面宽度 1280px 以上，短指标块不再被同一行长表拉高；工作区首屏没有大块无意义留白。
2. 题材/证据地图无有效节点时高度不超过 140px，并显示明确中文原因。
3. 盘中异动无资讯时列表高度由空态决定，不保留 456px 空画布。
4. last-good 快照刷新失败时，旧数据仍可见，页面同时出现中文失败阶段和单区块重试按钮。
5. 无缓存的失败请求显示中文失败原因和重试按钮，不显示英文异常或“成功但空数据”。
6. 红涨绿跌规则不变，移动端降为 2 列/1 列且文本不溢出。

## 非目标

- 不重分类或分级菜单。
- 不改变行情、新闻、AI 的真实数据边界。
- 不关闭、重启或控制通达信，不把浏览器或 HTML 作为交付入口。
