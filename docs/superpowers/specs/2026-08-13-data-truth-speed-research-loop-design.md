# 数据真实性与快速研究闭环设计

## 目标

在现有真实数据和证据契约之上，建立统一的 A 股交易日锚点、同日缓存边界、增量刷新和可钻取证据链，确保信息总览、个股观察、公司研究和量化分析不会混用旧日期、跨日缓存或来源不明的数据，同时保持便携 EXE 的快速首屏和稳定切换。

## 设计原则

- 所有页面使用同一上海时区交易日锚点；页面自己的本地时间不能覆盖数据交易日。
- 缓存只能保留同一交易日的完整快照；跨日缓存必须显式标记为历史快照或丢弃，不能显示为实时。
- 空响应、字段不足和较旧响应不能清空已有完整快照；只有更晚且证据完整的响应可以替换。
- 每个关键指标都能追溯到交易日、观测时间、来源、覆盖率和状态。
- 统计数字必须支持钻取到股票名称、代码、日期和来源；无法还原成员时明确写明“只有聚合统计”。
- 红色表示上涨或改善，绿色表示下跌或恶化；数据缺失使用中性状态色。
- EXE 是唯一交付入口；通达信只读，不关闭、重启或控制通达信。

## 主要组件

1. **TradingDayContext**：统一计算上海时区的自然日、交易日、盘前/盘中/盘后阶段和允许使用的最近交易日。
2. **SnapshotEnvelope**：在快照外层保存 `trade_date`、`observed_at`、`source`、`coverage`、`status` 和 `snapshot_id`，前端缓存与后端响应使用同一字段名。
3. **IncrementalSnapshotStore**：按数据域和交易日存储完整快照；刷新只替换更晚、同日且状态不低于当前快照的数据。
4. **EvidenceStatusStrip**：全站统一显示数据水位、来源、时间、覆盖率和可执行的修复原因。
5. **DrilldownTarget**：统计数字和图表交互统一产生筛选条件，直接进入股票明细或明确提示聚合不可还原。

## 数据流

```text
本地通达信/真实源
        |
        v
交易日锚点 + 字段证据校验
        |
        +--> 同日完整快照缓存 --> 页面首屏
        |
        +--> 后台增量刷新 --> 只替换更新更晚的完整字段
        |
        +--> 水位/缺口状态 --> 修复入口与钻取明细
```

页面切换只读取共享快照，不重新启动全站工作台；后台刷新按数据域合并请求，单个区块失败不清空其它区块。

## 异常与降级

- 交易日不一致：旧快照保留为历史证据，但不得进入实时指标；页面显示具体日期差和来源。
- 覆盖率低于门槛：状态为 `partial`，公开有效分母、缺失数量和受影响指标。
- 来源不可用：状态为 `unavailable`，保留最后一次完整快照并显示失败原因；不使用零值或随机值补齐。
- 新响应为空或观测时间更旧：丢弃该响应并记录原因，继续显示当前完整快照。
- 通达信专业接口缺数据包：显示不可用，不用普通行情字段替代专业字段。

## 验收标准

- 同一交易日内四个核心页面显示相同 `trade_date`，跨日缓存不会被标成实时。
- 刷新失败或空响应不会导致页面空白或历史完整内容消失。
- 统计数字可钻取时显示股票名称和代码，不可钻取时显示聚合边界说明。
- 关键指标显示来源、观测时间、覆盖率和状态。
- 前端/API 回归、生产构建、UTF-8/乱码扫描和便携 EXE smoke 全部通过；通达信 PID 与端口前后不变。
