# 全站速度、数据与信息架构统一设计

## 目标

在保留 Windows EXE 与现有 React 内嵌渲染器的前提下，把一树-A股观测台从“各页面分别请求和计算”收敛为“共享数据运行时生成快照，各页面只读取与增量订阅”。所有菜单优先展示可用缓存，在十秒内给出真实内容或明确的真实降级原因；后台更新不得清空、遮挡或闪烁现有内容。

## 不重写桌面技术栈

现有桌面壳首窗已经达到亚秒级，性能问题主要位于 API 冷启动、外部数据源、页面多接口并发、重复轮询和重计算。改写原生桌面 UI 会引入新的图表、缓存、发布和兼容风险，不能直接解决数据链路问题。因此继续使用现有 EXE、Python/FastAPI 与 React，通过运行时和数据契约治理解决速度与一致性。

## 性能服务等级

| 场景 | 目标 | 失败时行为 |
| --- | ---: | --- |
| EXE 可见窗口 P95 | 1 秒内 | 显示桌面启动阶段与真实耗时 |
| 菜单切换、已有缓存首帧 | 300 毫秒内 | 保留上一份有效内容 |
| 本地完整快照读取 | 1 秒内 | 返回最近可用快照并标明时间 |
| 本地最新行情读取 P95 | 3 秒内 | 标记数据新鲜度和缺口 |
| 未缓存首次查询 | 10 秒内 | 返回部分证据或明确不可用原因 |
| 点击、筛选、展开反馈 | 100 毫秒内 | 控件立即进入可见状态 |

十秒是用户体验门禁，不是对不受控外部网站的虚假成功承诺。外部数据源超时后必须终止该阶段，并返回缓存、部分结果或具体失败来源。

## 核心架构

数据链路固定为：

`来源适配器 -> 共享采集与裁决 -> 不可变领域快照 -> 页面最小快照 -> 单一增量流 -> 后台重任务`

### 共享采集与裁决

- 行情、指数、K 线由一个后端采集器维护，交易时段按 1 至 3 秒更新增量。
- 板块、市场宽度、涨跌停生态按 3 至 5 秒计算共享快照。
- 新闻按 15 至 30 秒集中采集、去重、分类、股票/板块关联和时效淘汰。
- 量化盘中触发按 5 秒增量计算，全市场重扫进入后台任务。
- 公司研究和财务数据按交易日冻结，缓存优先，必要时后台补充证据。
- 运维和数据源健康只在页面可见或用户展开时读取。

来源优先级按能力而不是页面固定：本地通达信/mootdx 优先提供行情与 K 线，腾讯用于实时补充和交叉校验，新浪、巨潮、同花顺承担各自唯一能力，东方财富只用于不可替代字段并统一限流。页面不得在打开时直接访问外部网站。

### 不可变领域快照

共享运行时只生成少量有清晰版本的快照，例如市场横截面、指数分时、涨跌停生态、板块资金、新闻关联、量化触发和公司研究。快照包含交易日、观测时间、来源、覆盖率、内容哈希、新鲜度和缺失原因。页面只能投影这些快照，不得重复全市场计算。

### 页面最小快照

每个一级菜单只有一个首屏契约，首屏只返回该页面必须显示的摘要、状态和缓存时间。大表、历史回测、详细证据和 AI 解释按可见区块或用户操作继续加载。页面切换时先读内存/本地缓存，再并行请求最新页面快照。

### 单一增量流

应用常驻层维护一个 SSE 增量连接，统一分发行情、市场、新闻、任务和告警事件。页面通过可见性订阅主题，不再各自创建重复的 1 秒、5 秒或 30 秒轮询。SSE 断开时由应用层使用一个退避轮询保底，恢复后自动关闭保底轮询。

### 后台重任务

全市场扫描、回测、AI 长分析、历史补齐和下载解压都进入统一任务队列。任务状态必须来自真实阶段：已处理数量、总数、耗时、来源和失败原因。知道总量时展示真实百分比；不知道总量时只展示阶段、已处理数量和耗时，不显示伪造百分比。

## 统一请求客户端

所有前端 GET 请求使用一个客户端，统一提供：

- 相同方法、规范化 URL、查询参数和响应类型的在途请求只执行一次。
- 页面卸载只取消该调用者，不错误终止其他共享调用者。
- 默认超时、中文错误映射、缓存命中、新鲜度和请求账本。
- 缓存优先与后台重验证，刷新失败不清空 last-good 数据。
- 页面/领域维度的并发上限，避免打开页面时请求风暴。

POST、导入、修复、发送告警等有副作用操作不能自动合并或重试，必须保留幂等键或显式确认语义。

## AI 运行规则

AI 不参与每个 tick 的同步路径。只有以下条件触发：

- 领域快照内容哈希或重要指标跨过阈值。
- 新出现已去重的公告、新闻或异动事件。
- 用户主动请求研究、解释或策略生成。
- 收盘事实冻结后生成一次盘后分析。

AI 输出必须引用输入快照时间、来源和缺失项；模型不可用时仍展示结构化事实，不把模板文字伪装成 AI 结论。

## 十四个一级菜单的唯一职责

| 菜单 | 首屏职责 |
| --- | --- |
| 信息总览 | 指数、市场宽度、情绪、涨跌停、板块、资金和关键异动 |
| 今日决策 | 市场风格、主线、机会、风险和执行纪律 |
| 个股观察 | 行情、K 线、事件、资金、盘口、异动和自选 |
| 公司研究 | 业务、财务、同业、估值、催化、反方和失效条件 |
| 首次涨停 | 首板事实、封单质量、板块归因和次日跟踪 |
| 尾盘选股 | 14:30 候选、盘中确认、AI 解释和失效条件 |
| 量化分析 | 因子、策略、TICK、Kronos、回测、闸门和样本外验证 |
| 监控中心 | 规则、触发、语音、飞书和送达状态 |
| 新闻热点 | 去重、分类、股票/板块关联、影响和来源证据 |
| 风险提醒 | 可执行的市场、自选、组合和个股风险 |
| 历史复盘 | 盘后报告、行情重放、回测历史和归因 |
| 数据设置 | 本地路径、OpenAI 兼容接口、语音和来源配置 |
| 本地运维 | 补数、导入、健康、任务、备份、恢复和日志 |
| 可转债 | 独立的转债行情、筛选、策略和风险 |

菜单不重新分级。信息总览的 50 个平铺入口收敛为盘中异动、市场情绪、涨跌停生态、板块题材、资金席位、量价榜单、新闻摘要和盘后复盘八个核心工作区。已有专项能力移动到正确一级菜单、二级钻取或详情区，不静默删除。

## 清晰度规则

- 同一事实只在最合适菜单完整展示，其他菜单只显示摘要和跳转。
- 数字统计必须可点击钻取到股票代码、名称、筛选依据和证据时间。
- 股票代码不能脱离股票名称单独出现；未知名称明确标记待补齐。
- A 股涨为红、跌为绿；状态色、来源色和事件色不得冒充涨跌色。
- 文字、卡片和图表采用统一密度与最小字号，不用大面积空白或重复说明。
- 页面有内容时后台刷新只能更新局部状态，不显示全页加载遮罩。

## 性能与真实性观测

后端性能样本使用规范化路由模板，而不是把股票代码、日期、任务 ID 和查询串当作不同接口。样本记录 HTTP 状态、响应来源、缓存状态和降级状态。历史旧样本保留但不参与当前版本门禁。

发布门禁覆盖 14 个菜单：每个菜单验证缓存首帧、最新本地数据、外部来源超时降级、刷新不清空和中文错误。门禁输出 P50/P95、缓存命中率、重复计算数和失败原因，任一菜单超过十秒且没有可用内容或明确降级即失败。

## 代码与资源治理

- 先以请求账本和依赖图确认重复链路，再删除代码；不按文件大小盲删。
- 测试、文档和源码不进入 EXE 时不会影响启动，不为“看起来精简”删除。
- 拆分超大模块以职责和测试边界为依据，优先拆 `main.py` 的装配/中间件以及市场概览和量化策略的采集、计算、投影。
- 路由按领域共享服务，不把一个巨大聚合接口替换成另一个巨大接口。

## 发布与恢复

所有用户可见修改最终重建便携 EXE。构建必须保留 `config`、`data`、`news`、`cache`、`logs`、`models`、`exports` 和 `backups`，运行真实 EXE smoke、恢复演练、全量 API/Web 测试、Ruff、生产构建、乱码扫描和 Git diff 检查。验收记录必须包含真实耗时、数据状态、EXE 路径、提交和哈希。
