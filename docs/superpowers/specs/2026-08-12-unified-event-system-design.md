# 统一事件体系设计

## 目标

在不建立第二套新闻库、不制造事件方向或影响数据的前提下，让新闻、公告、热点、盘中异动和 K 线围绕同一个真实 `event_id` 使用一致事件语义。

## 选定方案

保留 `NormalizedNewsEvent` 作为事实层，不改变原始证据、引用、关联对象和人工修正流程。新增独立的决策事件投影：事实层负责“发生了什么”，投影层负责“属于哪类、当前能否判断方向、还要观察什么”。

未采用直接把全部决策字段写回新闻事实模型的方案，因为方向、强度和价格反映程度会随解释、行情与时间变化，不应污染追加式原始事实。未采用新建事件数据库的方案，因为会产生重复 ID、重复去重和不同页面不一致的问题。

## 八类事件

1. 政策宏观 `policy_macro`
2. 行业板块 `industry_sector`
3. 公司公告 `company_announcement`
4. 业绩财务 `earnings_financial`
5. 资金龙虎榜 `capital_dragon_tiger`
6. 价格成交异动 `price_volume_anomaly`
7. 风险事件 `risk_event`
8. 传闻待核验 `rumor_unverified`

分类只依据原始 `event_type`、标题、题材和复核状态的确定性规则。不能确定时进入 `rumor_unverified`，不得强行归类为利好或利空。

## 决策事件投影

每条投影包含：

- 原始 `event_id`、标题、发生时间和类别；
- 影响股票、行业、题材；
- 方向和强度：仅采用未降级、置信度达到门槛的真实解释，否则为待核验；
- 可信度：来源复核、直接关联度和来源数量的可解释合成，不冒充概率预测；
- 持续时间：没有事实依据时为未知；
- 价格反映程度：没有事件前后行情证据时为未知；
- 后续观察指标：由事件类别映射到固定核验清单，不生成公司特定事实。

## 去重与稳定性

- 事实去重继续使用新闻采集内容哈希和事件 `event_id`；
- 所有下游投影按 `event_id` 唯一；同一 ID 只保留截止时间前最新有效解释；
- 同一交易日内页面只追加新真实 ID，不因刷新临时缺失而删除；
- 交易日变化时由页面快照边界重置；
- K 线事件、新闻关系图和异动列表继续传递原始 `event_id`。

## 展示语义

- 事件归属色独立于红涨绿跌；红绿只表达已经核验的正负方向或行情涨跌；
- 页面显示紧凑图例，明确“颜色表示事件归属”；
- 未知字段显示“待核验/暂无行情证据”，不显示 0 或默认积极/消极。

## 验证

- 契约测试覆盖八类归类、未知方向、可信度边界和观察清单；
- 投影测试覆盖按 `event_id` 去重、最新有效解释和截止时间；
- K 线与新闻图谱测试验证继续共用事件 ID；
- 最终在 Phase 9 执行全量测试、生产构建和 EXE 烟测。
