# 阶段新闻证据收敛设计

## 问题

“今日研判”把盘中快照引用的全部新闻逐条展开。当前生产数据中有 113 条，其中大量新闻早于盘中证据窗口，也不属于正在观察的股票。建议被长新闻流淹没，且历史新闻会被误解为当前决策依据。

## 目标

- 盘中快照只引用证据窗口内、与实际评估股票关联的已验证新闻。
- 响应层防御性忽略已存在快照中早于窗口的新闻，不把它们标记为“缺失”。
- 界面按时间倒序展示，默认显示最新 3 条相关新闻，并保留完整展开能力。
- 缺失、部分可用和不可用状态保持显式，不用推测内容补位。

## 方案

后端在确定性盘中评估时累计每只已评估股票匹配到的事件编号，去重后稳定排序写入快照。响应组装继续以快照编号为准，但会根据 `window_start` 和事件 `normalized_at` 排除越界历史事件；真正找不到或未通过验证的引用仍进入 `missing_event_ids`。

前端将相关事件按 `occurred_at` 从新到旧排序。事件超过 3 条时，首屏只渲染 3 条，并显示“显示 3 / 共 N 条相关已验证新闻”；用户可通过单一按钮展开其余事件或收起。该状态只影响呈现，不修改证据数据。

## 边界

- 不改变新闻审核规则、AI 输入规则或确定性建议字段。
- 不删除历史快照，也不重写审计记录。
- 不新增导航、部门或交易功能。
- 市场级事件只有在确定性规则明确引用时才进入盘中快照。
