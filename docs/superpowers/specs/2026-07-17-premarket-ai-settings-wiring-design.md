# 盘前 AI 设置接线设计

## 目标

让“数据设置”中保存的 OpenAI 兼容配置无需重启即可用于盘前冻结证据的补充解释。确定性程序仍独占行动、置信度、数值、风险和合规门禁；AI 只能解释已经冻结的证据与结论。

## 方案选择

采用同步热加载网关。盘前调度本身是同步流程，网关复用生命周期内已有的 `httpx.Client`，每次解释前重新解析当前设置，并继续使用 `DecisionAIGateway` 的证据范围、数字和交易计划校验。

未采用把整个盘前调度改成异步的方案，因为这会扩大调度器、阶段运行器和测试的改动面。也不采用只在应用启动时读取一次配置的方案，因为保存设置后仍需重启，不能解决当前问题。

## 配置修订与幂等

`AISettingsRepository.save` 在本地密钥文件中同时保存一个随机、非敏感修订号。读取设置的公开模型保持不变，API 也不返回修订号。每次显式保存都会生成新修订号；API 密钥绝不进入修订号或任何哈希。

盘前输入哈希加入网关提供的公开配置身份：配置状态、兼容端点、模型、提示词版本和非敏感修订号。这样从未配置切换到已配置、切换模型或重新保存密钥时，会在相同冻结证据之上追加一个新快照；旧快照保持不可变。没有配置身份接口的测试替身和旧网关继续使用原有幂等行为。

## 网关与请求

`OpenAICompatibleDecisionProvider` 向 `{base_url}/chat/completions` 发送同步请求，使用 `temperature=0` 和严格 JSON 响应格式。用户消息只包含 `DecisionAIGateway` 已构造的冻结证据、确定性结论、允许引用的证据 ID 和响应模式。

`ReloadableDecisionAIGateway` 在每次 `explain` 时读取最新设置。未配置时不发出 HTTP 请求并返回 `unavailable`；已配置时使用 `openai-compatible` 提供器。结果的证据时间使用请求的冻结时间，避免网络调用结束的毫秒差被误判为越过盘前截止时间。

## 失败与安全

- 超时、HTTP 错误、非法 JSON、越界证据、数字、价格、仓位或交易计划全部降级为 `unavailable`。
- 降级不会删除确定性建议；快照保持 `partial` 并记录 `ai_unavailable`。
- API 密钥不进入提示词、`repr`、异常、返回模型、快照哈希或配置身份。
- 本切片只接通盘前 AI；盘后复盘的 AI 解释属于后续独立切片，避免同时改变两个阶段的持久化语义。

## 验证

测试覆盖未配置零请求、保存后无需重启、严格 JSON 请求、模型与修订变化、密钥不泄漏、相同证据追加新快照、生命周期使用共享同步客户端。完成后执行全部 API 测试、Ruff、全部 Web 测试、生产构建、严格 UTF-8/乱码扫描、`git diff --check` 和真实未配置运行态验收。
