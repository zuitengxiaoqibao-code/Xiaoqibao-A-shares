# 十四菜单运行时总账

## 统一结果契约

每个菜单首屏均需生成以下验收字段：

- `menu`：稳定菜单标识。
- `state`：`ready / partial / stale / unavailable / error`。
- `latency_ms`：从进入菜单到出现可用内容或明确降级的真实耗时。
- `cache_frame_ms`：有缓存时从进入菜单到缓存完整首帧的真实耗时。
- `usable_content`：是否至少展示一份结构完整、可交互的真实内容。
- `reason`：没有可用内容时必须填写具体数据源和失败阶段。
- `observed_at / trade_date / source / coverage`：数据时间、交易日、来源和覆盖率。

发布时由 `scripts/verify-menu-performance.ps1` 验证十四项完整性、十秒结果上限、一秒缓存首帧上限和空结果原因。长期目标仍是菜单切换缓存首帧 300 毫秒，本轮发布硬门禁先采用 1000 毫秒以覆盖低配置测试机。

## 页面打开规则

1. 同菜单同标的缓存存在时立即显示完整 last-good 内容。
2. 同时请求页面最小快照，成功后局部替换变化区块。
3. 大表、历史、AI 和全市场重算不进入首屏关键路径。
4. 十秒到达时仍未完成，终止当前同步等待并展示来源、阶段和可重试动作。
5. 后台任务继续时只更新局部状态条，不显示全页遮罩。
6. 切换菜单取消当前调用者，不取消仍被其他页面或共享运行时使用的请求。

## 数据复用关系

- 市场横截面同时供信息总览、今日研判、首板、尾盘、量化和风险使用，只采集和计算一次。
- 个股行情/K 线同时供个股观察、公司研究摘要、量化标的和事件关联使用，只维护一个标的快照。
- 新闻关联快照同时供新闻热点、事件 K 线、公司研究催化/风险和监控中心使用，原始新闻不可被各页面重复抓取。
- 任务、来源健康和性能账本由本地运维完整展示，其他页面只显示与当前操作直接相关的一条状态。
- AI 解释引用快照版本与内容哈希；相同输入不重复调用模型。
